# WF V40 自主阅读能力考试｜密封章节包

## 考生与边界

考生只能是 WriterForge 正式 LEARN/WRITE 执行链，不是 ChatGPT、考官脚本或独立评审模型。原始输入是本目录 reader_packet.txt；manifest.json 提供版本与来源校验而**不提供文学答案**。原书是《老殘遊記》第七回，原著正文完整保留，考卷为适配旧版原著解析器而把**考试包的单章槽位**编号为“第一回”，不表示它属于原书第一回。

**本轮极限基础测试：禁止任何远程/本地语言模型、外部搜索、人工或考官代答。** 这种设置用于检验 WF 现有 Python/Skill 代码在没有推理模型时究竟能做到什么。不能凭程序的“你是 WF 读者”提示词就把另外一个模型认作 WF 的内生能力。

## 任务（不得预写答案、不得把考官的目标当原文事实）

1. **R-IO 阅读入口**：完整读入 reader_packet.txt，校验出处、原稿完整性、章节位置、文本字数；不接受只打印文件名或只查关键字作为完整阅读证明。
2. **R-TRACE 顺序阅读**：按原文顺序形成至少六个相互独立、可核查的观察，每项含源文准确短引、先前读到的位置与到此为止人物已知/未知信息。不得提前使用后文解释冒充前文推测。
3. **R-ANALYZE 自己分析**：至少两条“人物见闻→形成判断→采取行动→产生后果”的因果链；说明不同人物的信息边界，对每一链给出来自本章的独立证据和至少一条可能替代解释。不允许只罗列词频、地点和人物名字。
4. **R-CRAFT 总结文学选择**：归纳作者实际采用的视角/对白/延迟揭示手法，给出原文位置，解释如果替换叙事顺序会怎样，并标记哪些解释还不能确认。
5. **W-CLOSED 原创迁移**：完成一篇250–450汉字的新故事。人物、地点、物件与原章不同；设置有限知识下的错误或犹疑、明确的行动、现实后果、之后可回查的揭示。只可读取 WF 本轮产生的学习记录，不能引用考官样文、已看过的原文剧情，也不能调用外部作者。
6. **R-REVIEW 自查**：按真实自写正文分别引用“观察、行动、后果、揭示”的真实片段，承认其中的断链与不确定处；不能临时伪造写前已思考内容。

## 按能力单独验收

- 完整接入/解析/入库成功 ≠ 理解人物和叙事。
- 对原文采用确定性词面标签 ≠ 独立文学分析。
- 能输出一份 prompt ≠ 能自己写作。
- 文学自评 ≠ 独立验证，结果不晋级正式技能。
- 所有回答必须由 **实际运行的 WF** 产生并保存阶段证据；无法执行时只写明 BLOCKED/NOT_IMPLEMENTED 和技术原因，不准由考官补齐。
- 若零模型测试停在 R-IO，修的是阅读/文本保存技术；若到达 R-IO 却停在 R-ANALYZE，应明确区分“没有独立语义引擎”与“章节解析错误”，不得静默改成调用 DeepSeek/GLM/Kimi 代答。
