# WriterForge V106：E 与 F 真实因果预演的小规模对照（预注册）

## 目标

验证从 V104 深海采矿站原始失误得到的“切断主电却依赖主电钻机制造声波”的负例，在相同短故事和WF自行制定的两段事件提纲下：
- 旧 E 情感滚动是否会在创作中跳过设备真实供能条件；
- 新 F 提前列替代未来后，是否在正文中更好地维持资源、行动、知识、损失与下一选择；
- 新规划是否损害自然写作，变成机械说明书或人为牺牲。

重点：**这不是已证实的文学质量盲评**。这是对 V105 在真实外部文字生成器上能否执行的早期行为核验；严禁只按JSON、SHA、词句标记宣布 F 变好。

## 单一 WF 注册模型与公平性限制

- 真正调用的只有已注册于 WF 的 DeepSeek Flash：本轮**没有第二个“文学考官模型”或写后润色模型**。
- 现有 WRITER 的 `AutonomousWriting.run` 不改调用算法；隔离 runner 只把其本地LM Studio传输端口替换为**同一个 WF 的 `DeepSeekFlashModel.ask_json` 适配器**。这是实在的模型回复，不是 unittest.mock 的假正文。
- 第一步也由这同一模型根据旧V104**自己选的场景 s01**提出两段事件草案；校验后该不可变 `turns` 同时用于 E/F，不由考官提供剧情答案。原 V104 小说正文完全不发送给两臂，只保留其自选场景构想。两臂共用一份固定场景、世界硬限制、角色原始目标。
- 使用仅含一条“中性软件连接测试”的**临时 synthetic published snapshot**满足正式 WF 本地 verified route 的结构性入口约束，并显式标为 `synthetic`。该条目不属于前15章真阅读经验；禁止说这是 V82 经验在 WRITE 的证明。两臂各用独立的空临时 DB，无已接受候选互相干扰。
- 先后顺序固定 E 然后 F；同一模型、同一初始背景、同一两段事件提纲。F 章计划 output 预约最大2400 tokens，E 650，实际计算量可能不同，因此**这不是精确等计算预算的文学效能因果实验**，不能因F好/坏自动归因于预测本身。
- 一次性原始R2 CAS 预注册 `created=true` 后最多 **9 次真实 DeepSeek 请求**（1次共同两段提纲 + E 4次 + F 4次），最大预约输出11,600tokens、保守总上限150,000tokens，网络超时/格式失败绝不自动重试；留存原始供应商JSON、请求SHA和全部失败。不调用不在用户许可范围的外部评论模型。
- 如果第一步提纲或某一臂模型结构失败，保留 `RED`，可继续独立尝试另一臂但不恢复旧臂；不追加“救火”重抽。真实模型输出成功后，先存私有R2原始答案，然后程序核验；主服务无需改动。
- 写作输出若两组真实字符数量差超过10%，只作定性逐句分析，拒绝“哪组文学更强”的量化排名；无独立人类评审时始终 `UNDETERMINED`。
