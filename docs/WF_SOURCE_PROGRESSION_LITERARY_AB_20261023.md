# WriterForge：真实正文推进的文学 A/B 与负面证据（2026-10-23）

唯一开发分支：refactor-unified-scene-delivery-audit。用户本轮核心目标是让 WF 自己完成不同场景原创小说，通过实际作品发现人物、因果、节奏、文风与结尾问题，再让现有创作流程真正帮助 AI 写作。没有建立新 Skill 或独立记忆系统。

## 第一轮：从真正文发现文学缺陷

来源：[WF 四类自主写作 #39961720469](https://github.com/66tyu55/WriterForge/actions/runs/39961720469)，原始供应商响应、各段原稿、完整候选与审计均保留。

- 打斗：右臂伤、火髓果与破桥影响了交锋，却不断让果子伸出又收回，末尾仍停在僵持，变化少。
- 计谋：守夜人、石灰、灯号、皮囊有具体行动，但唐蜃会将脚印和皮囊误当成对手必然被骗的证据；叙事视角与推测边界含混。
- 搞笑：真巡察使已来到门口，后续段却继续围绕验伞骨与规矩解释，不给误会充分的新后果。
- 心理：烧毁伏击图、推迟复仇、转查获救孩子，已经写出人物认识变化对应的行动，必须保留这种细小但真实的选择，而不强制每段反转。

这是实际原稿的编辑诊断，不是人工专家的独立盲评。

## 只改现有作家流程的一条创作指导

在 writerforge/writing_assist.py 加入可选的 _source_progression_literary_cue，供已写出上一段真实候选的后续事件使用：不要重演已经完成的准备动作；人物从当前的认知与代价继续选择，通过行动的新后果、对方的新反应、关系变化或有代价的克制让场景前进；不要把人物猜想写成未经来源证明的旁白事实。仍允许沉默、失败、放弃、延期、转向，不强迫喜剧笑点、心理变化或者伏笔必须当场完成。

这仅使用 continuity_guard 已有的可选文学提示 lane，不强占 NPC 知识与物理时态硬限制，不增加模型调用，不改变 Canon 与统一 THREAD 所有权。未送达的提示在现有 v121 prompt receipt 中明确记录 false。

## 真正同源创作配对，不以软件绿灯冒充文学提高

[真实四类 A/B #39964830150](https://github.com/66tyu55/WriterForge/actions/runs/39964830150) 四个 GitHub job 全部 success。

每类两臂共用先前 WF 自己产生并封存的真实模型章节计划及两事件计划（来自 #39961720469 的原始 Artifacts，核实 SHA）；采用同一模型 DeepSeek Flash、同一源前史、同一写作入口和相同输出上限，每臂**只重新生成两段正文**，每段 max_tokens=1450。四类总共 16 次真实正文供应商调用；无自动重试，测试没有复制旧正文作新结果。仅变化后续写作提示是否启用。每类均生成完整原文，源文本、供方 wire、模型 JSON、source receipts、遮标稿 BLIND_PAIR.md、盲标映射独立文件 UNBLIND_MAPPING.json 都在原始 Actions 证据内。

重要限制：新提示增加输入 token，实际供应商总消耗未做相等约束。只有模型、前史、模型生成的计划、正文请求次数、每段 max_tokens 一致；并非随机种子和实际算力完全匹配，样本每类仅一对，不能推导长期文学胜率。
