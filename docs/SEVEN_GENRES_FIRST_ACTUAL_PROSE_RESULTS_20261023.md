# WF 七类小说：书生 Atria 真实 A/B 第一批实测（2026-10-23）

用户明确同意通过已有书生 Discovery 接口，对小说的**剧情、高潮、打斗、计谋、恐怖、搞笑、心理**七类场景执行真实生成核验。

## 测试设置

生产 `main`、Railway、R2、正典均无写入。使用同一个 `Atria-Dawn-Preview`，相同的完全合成先前情节／当前写作目标；每类裸模型 1 篇与实际调用 WF V114/V117/unified narrative_core/V118 提示组装代码的引导版 1 篇。模型请求由 OpenAI-compatible `https://discovery-api.intern-ai.org.cn/v1/chat/completions` 的 SSE `stream=true` 执行；`finish_reason=stop` 且收到 `[DONE]` 才算成功。每次限 3,100 `max_tokens`，无自动重试。此为**调度提示 A/B**，并非完整 WF 生产写作运行；没有独立人类盲评，原稿及 prompts 存于 GitHub workflow artifact。

初始七类 matrix run：https://github.com/66tyu55/WriterForge/actions/runs/39937669584

前五个完成配对共 **10 篇真实原稿**；现有 WF narrow source checker 0 硬性警告，并不代表没有文学和因果缺陷。平均汉字数裸版 1048.8，WF 引导版 1209.4，WF 平均多 160.6 字。预注册机械合规区间 680–1250 汉字：裸模型 4/5，WF 3/5，不能宣称 WF 改善长度服从。已完成10篇所报告 `total_tokens` 合计 17,238，**这是模型上报用量，不是账号扣费证明**。

以上属按原稿文本的编辑观察，不构成独立盲评或统计显著性结论。特别是“逻辑检查报告 0 错误”只证明限定识别规则未触发，绝不证明人物自洽、笑点有效或心理真实。

## 原因排查与补测纪律

此前独立 [Atria SSE 千字单次验证](https://github.com/66tyu55/WriterForge/actions/runs/39936371137) 成功 926 汉字、155.3 秒、980 SSE 事件；说明 API Base URL 与流式解析可以正常工作。

[reasoning_effort=low 单次受限探测](https://github.com/66tyu55/WriterForge/actions/runs/39939117825)：并未改善高潮类问题，3,100 Token 仍全部被推理占用，`finish_reason=length`、可见正文 0，且返回 HTTP 成功。因此不能靠文字层的 `low` 自我宣称推理已降。

目前另起 [仅高潮与心理的 6000 Token 配对 SSE 补测](https://github.com/66tyu55/WriterForge/actions/runs/39939718654)。它只改变**每次输出预算上限**，同一类别内部裸／WF 两版使用相同参数；不篡改初始失败结果，不将新批次混成同预算跨类别统计。每个工作最多 2 次、整个补测最多 4 次、失败不自动重试，完整原文与 useage 保留。

## WF 底层应该吸收的实测缺陷

1. 引导提醒越多并不天然提升文学创作；WF 在打斗／计谋中超长，且会产生新资源规则而无法自证来源；文学提示应按场景功能选择、限制强度。
2. 计谋中人物推断不能升成作者事实；既有 NPC belief/known 图谱应继续区分认识和真相。
3. 喜剧需要让事先建立的反差或误会**实际兑现**，不能只堆尴尬心理细节；高潮、恐怖、心理也不能用一个“多加细节”的规则统一。
4. 模型输出上限必须为 `reasoning_tokens` 留有可见正文预算，HTTP200、SSE 连接正常、甚至出现大量推理 Token 都不代表生成成功。
5. 需要下一次独立遮盲的文学评审；任何真实正文缺失的类别都不得宣称已完成 A/B。

所有素材均为合成原创，不调用或公开用户既有私人长篇。任何结论以封存输出和具体证据为准。
