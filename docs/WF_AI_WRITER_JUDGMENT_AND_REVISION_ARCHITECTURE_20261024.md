# WriterForge：AI 作家自我判断「为什么删、什么时候删」底层架构（2026-10-24）

## 结论与现状

核心边界：**AI 是作家，负责构思、感受作品有没有达到当前写作意图、提出修改方向、写出全部新文字；WF 是工作台和事务系统，负责将真实前史与当前草稿交给 AI、在有限的故事边界安排暂停机会、执行 AI 的选择、校验改稿原文、维护版本及回滚。不得把 WF 的关键词、分数、规则或模版冒充 AI 的文学判断。**

现有 G 路线的 self_edit_rounds=1/2 是试用版本：在每个事件 turn 完成以后固定要求 same-model 返回 KEEP、DELETE、REVISE、REPLACE_SCENE 和一句 reason；V119 负责按原文范围修改，V96/V117 负责检查字面/来源；工作台本身没有真正的主观审稿能力。**本版本尚不能说明「AI 自己决定什么时候需要回头看」或「为什么某个场景文学上不满意」已经做成**，也没有支持 AI 从任意字符 mid-token 自发暂停。已验证的一次真模型试验和零新模型回放只能证明局部自审/源锁定执行和某些负例。

## 正确的三层边界

### L1 书写中的 AI / 不是宿主程序

这同一个写作模型先确定文学意图：人物想得到什么、所知和未知、阻力是什么、当前想带给读者何种感受、哪些悬念暂缓、为什么某个选择对人物有代价。然后写真实正文。一段完成后，模型可自己决定 KEEP_WRITING / LOOK_BACK_NOW；它并不是在回复某个固定评分标准，而是读到自己真实写出来的文字、比较目前意图和实际读者会看到的效果。

若 LOOK_BACK_NOW，AI 需说清：
- 触发时机 why_now：到底哪里让当前往下写变得不自然或站不住？
- source_excerpt：原文哪一句或哪一处现象提供了不满意的证据；如果问题是「该写的根本没写出」，允许指出场景整体缺口，但不可伪造引用。
- dissatisfaction：作者自己判断不满意的文学理由，例：行动没有改变处境、角色无信息却先说出秘密、对话像解释大纲、打斗空间不清、节奏太早泄密、修辞抹掉人物声音、承诺的代价没有落地。
- consequence_if_unchanged：如果不改，后面会有哪些人物、时态、情绪、情节或读者预期遭到误导？这仍然只是 AI 的假设，不是宿主已知的客观真相。
- desired_effect：修改后想达成的读者体验和人物选择，而非直接塞进结局。
- scope/operation：选择删句、改小段、改大段、丢掉整场；也可以最后决定 KEEP，不为了凑修改率强行更改。

问题分类可以是模型自己的自然语言；WF 不应通过关键词、字数阈值、情绪评分决定该 DELETE，或为了快速转折替它制定小说发展。

### L2 WF 写作工作台 / 不提供文学结论

WF **只负责在可观察、可恢复的边界提醒 AI 是否要往下走**：一个完成的句群/自然段、一幕戏或一个因果事件之后；下一段或下一章正式获得前一段状态之前；完成一章的候选稿时。作者仅给一次创作任务，模型每次自己选继续还是回读；并非每看到一个句号就强制重写。

现有实现只能在 G 事件段完成后暂停，因为普通非流式模型 API 无法中途读取其私有生成思考。要支持“写到半句不满意就擦掉”，必须让 **AI 把生成拆成可观察的较小稿片**，或使用真正支持流式、可取消、可继续的写作 API；宿主不得假称能查看模型内部想法。先从已有两段事件边界打通，之后逐步提供句群/段落的可观察候选窗口；模型仍负责生成所有文本，工作台不填词。

WF 可触发 **事实安全复核**（例如明确来源下 UNKNOWN 人物意外谈论秘密），但这个提示不是文学裁判，也不能直接选择删除何处；AI 要么写出合法的信息获取经过、要么改写对话或放弃这条计划。安全校验只能证明可引用/未越界，不证明写得好。

### L3 V119 / V96 / Novel Studio / Unified graph 的事务执行

模型提供选区与 replacement，WF 仅：
1. 锁定当前候选 source SHA、章号、事件号、原始文字；不允许旧废稿伪装新源。
2. 验证 AI 指向的原文唯一出现；若 Unicode 数字偏移错误但原句唯一，程序可重新定位 **位置**，绝不推断文学意义。
3. 使用 V119 执行确切范围修改；无文字外漂移。
4. 重新用 V96 实际来源引句、V114/117 物件和时态、同一人际 FACT/UNKNOWN/THREAD 源事实预检；失败就保留上一个候选，给 AI/作者看真实失败，不把模型说「写好了」当 proof。
5. 被删改的段落对应的**尚未确认的状态推断与后续计划**必须一起作废或重新推导；保留上一个完整、签名的章节快照，避免删了一次领取密令的动作，却让后章继续使用已领取密令。只有被接受的最新候选进入下一步的候选图，并且不能自动晋级 Canon。
6. 本作业的弃稿和历史 SHA 留在已有私有 job 限额内，人工点击“丢弃本次未完成稿”只删除这个 job 的本地临时版本；用户手写 draft.md、旧完稿、原著 R2 及历史实验不可删除。

## 完整循环的目标状态机

START_ONE_AUTHOR_REQUEST
  → AI_DESIGN_SCENE（可修改的计划，人物目的与有限视角）
  → AI_WRITE_VISIBLE_UNIT（AI 输出真实下一段/句群）
  → AI_DECIDE_WHETHER_TO_LOOK_BACK（AI 自己选择 MOVE_ON / REVIEW_NOW）
  → MOVE_ON：工作台在当前候选记录源版本，继续写
  → REVIEW_NOW：AI说明 source_excerpt + why_now + consequence_if_unchanged + desired_effect
  → AI_PROPOSE_EDIT（KEEP / DELETE / REVISE / REPLACE_SCENE，由 AI 提出实际替换全文或片段）
  → WF_VERIFY_SOURCE_AND_STATE
    → PASS：选择新版候选，并对后续未被确认的草稿重新规划
    → FAIL：维持旧候选，显示失败，AI 可以按剩余额度决定是否换方向；不能无限重试
  → 下一段或下一章
  → END_UNACCEPTED_CANDIDATE（作者确认权保持独立）

**关键区别**：是否要回头、为什么不满意、删后想表达什么由模型决定；修到哪儿、文字能否在当前来源上合法应用、会不会意外删作者已接受作品由 WF 决定。两个决定不能倒过来。

## 实验和工程验收应分别计算

工程可以证明：
- 每次自审是该任务同一实际模型的真实调用，而非 WF 拼出“该删了”的句子；
- AI MOVE_ON 时没有伪造的修改；REVIEW_NOW 时有真实原文和自己的简短判断；
- 仅在 AI 合法提供真实原句、确切修改内容时 V119 才可改稿；
- 改动失败回滚，删除不越界、不会导致人物认知/物件/跨章状态残留；
- 用户只发一次请求，自动有限循环，最多允许每 turn 两次修订、每 job 八个额外模型调用；所有预算与已弃原稿可追踪；
- 多角色争执、安静心理、侦探隐瞒、动作重复、语气变化都有正反样例，若 AI 认为「留白更好」允许 KEEP；
- 已写完整章节、用户之前接受过的章节、R2 真书和 main 不得受影响。

文学不能仅靠软件测试证明。必须做真实 WF 同源前史/同一模型的多场景对照，特别是普通版本、自发回顾并成功修订、以及 AI 错误修订被回退的版本；先匿名读作品，再揭盲，记录正文哪一句因人物动机、信息、节奏、氛围或代价不可信而出错，保留负迁移和删除导致的后续反常。

## 当前缺项与落地次序

1. 首先加入独立的 **AI 写作时机选择**（MOVE_ON / REVIEW_NOW），不是每段强制输出 DELETE 候选。模型在实际段落边界自己决定是否回读。下阶段已有结构化简明理由和真实证据引用可验证。
2. 再把「为什么不满意、什么效果要保留、若继续写有什么风险」传给同一 AI 的源锁定修改建议，由旧 V119 处理；不要增加独立文学评分机。
3. 最后才做可回头超过当前事件段、长场跨段删除的事务树回滚/受影响候选分支重建。复用已有 StoryWorkTree 和 V117 checkpoint，不开第二记忆库。不能为了实现大段作废直接无界增加 1800 字 V119 修改限额。
4. 实验小范围的自我激活决策先开 opt-in，不改变已有 G 自主修订默认、不修改 A–F；真实文学验证失败应继续恢复旧分支，不强制推广。

这不是替人类作家模拟一个“灵魂”或窥视隐藏思考，而是创建**模型自己可以做真实写作取舍、后悔、撤销和重新选择**的可观察工作条件。这项文学能力是否真正有效，只有实际新作品能证明。
