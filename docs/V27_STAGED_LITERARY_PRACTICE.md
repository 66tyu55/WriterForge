# V27 小规模文学训练阶梯：从短句到因果场景

本阶段以自主创作能力为优先，实时辅助界面暂不继续扩展。原著分类库是训练材料，不是成熟作家的证明。当前训练不是模型参数微调，也不替代作者和真实读者评价。

## 顺序练习

1. 原文短句理解：核对实际 source_spans、原文子串、显式事实/推断/不确定，模型原创12-65字短句。候选大类只记录为 model_proposal_not_semantically_verified，不能写入 V25 人工核实的 verified。
2. 单类别完整句：一条已经人工核实的类别来源，生成35-120字，避免形容词堆砌。
3. 两种类别组合：两种不同的已核实顶级类别，生成65-180字，必须有实际作用和因果关系。
4. 三种以上类别组合：至少三个不同已核实顶级类别，生成100-300字，围绕同一人物目的，而非素材拼贴。
5. 完整段落：180-700字，强调视角、场景转折、动作和人物情绪联系。
6. 完整因果场景：420-2200字，明确人物目的、冲突、不得不做的决定与后果。

训练关卡要求 V25 已人工确认的来源；缺少准确分类便停止在当前关卡，明确报告缺失，而不是用发现几个关键词冒充“已理解”。每个来源实例继续保存，组合只是临时选用几个参考维度，不是合并或删除原著案例。不同来源的素材不得冒充同一原著场景的事实。

## 独立评价与自我修订

前四级只做来源、长度、重复和类别闸门，不自称文学水平已达标。
第五、六级可用既有 lit-critic 本地服务，对实际原创稿产生有来源的独立编辑意见，再用本地模型最多修订一次。保存原稿、评论和修订稿；修订后没有复评或真实读者接受，不能断言“能力提高”。

lit-critic 需要真实本地服务及包含 CANON.md、STYLE.md 的工程；无法访问时记录 critic_failed，不能悄悄用另一个 AI 自评代替。所有训练尝试都保存在已有 SQLite 的 literary_training_attempts 中，单项目最多400条，达到容量上限必须先归档；私人 R2 可按批次备份整座数据库。不新建竞争性的文风知识库，不自动升级 Evolution 技能。

## Windows 本地试练

第一步：确认数据库里有真实发布的学海快照。LM Studio 本地模型准备就绪后，运行：

    python -m pip install -e ".[r2]"

检查当前这一本原著能到哪一关（内部开发诊断，不是让作者搜索素材）：

    writerforge --db corpus/xiyouji.sqlite3 literary-readiness --project literary-lab --work-id xiyouji-gutenberg-23962 --goal "为一个陷入两难的武侠人物写出选择与后果"

先练第一关：

    writerforge --db corpus/xiyouji.sqlite3 literary-practice --project literary-lab --work-id xiyouji-gutenberg-23962 --goal "为一个陷入两难的武侠人物写出选择与后果" --model "本机实际加载模型的ID" --through-stage 1

未来具备2/3个不同 verified 类别证据后，才可尝试 through-stage 3/4/5/6。想使用真正 lit-critic 对第五、六关给出编辑批评，另外传入 --critic-project 及其原有小说工程路径。

本地训练数据保存到 SQLite；成功后可用 --backup-r2 自动同步到自己的私有 R2。任何私人小说或训练候选都不会自动发布公开 GitHub Release。

## 原著真实数据审计

现有三部已完整入库的中文古典小说，在 GitHub CI 每次顺序训练后都会生成 literary_ladder_readiness.json，标出真实来源可用程度、每关是否有足够人工核实类别，以及模型和独立评论是否实际调用。
未经验证的八轨标签不能伪造成独立文学评论。原有50部不同作品后统一分析和技能大修的门槛仍然保持；本阶段只有局部分类与组合训练试验。

## 尚未达到的能力

目前没有证明模型真正理解了这些句子的作者意图、复杂人物关系，或者组合输出具备小说家的艺术品质。缺少 verified 类别时，多类别练习会明确 BLOCKED。实际的本地模型输出、lit-critic 真评价和读者反馈在拥有运行环境后才能执行，GitHub 的模拟模型测试不属于文学成绩。
