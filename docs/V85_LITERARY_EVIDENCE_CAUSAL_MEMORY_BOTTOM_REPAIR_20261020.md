# WriterForge V85｜文学证据—人物知识—因果假说底层边界（2026-10-20）

> 此文件是开发隔离分支 `v85-literary-evidence-and-causal-memory-gate` 的实际修复记录，不是声称文学能力晋级。以用户请求“仔细点，涉及WF底层”为准：修已有LEARN/R2与FactJournal之间的证据接口，不重训小说，不触发付费模型，不覆盖旧证据，不在 `main` 自动发布。

## 1. 实际底层根因（代码验证）

1. `writerforge/v80_large_chapter_batch.py` 的LEARN文学分析仅把模型选择的来源 `unit` 变为原文单位SHA；它能说明“引用了哪一单位”，不能证明假说解释哪句话、人物当时知道什么、模型是否编造因果或伏笔。
2. `writerforge/fact_journal.py` 既有V57–V59真实工程能力：明示同书跨章身份、故事时间与记录时间双时轴、角色/读者知识隔离、凭现有记录的时间快照回查。其本身仍不能验证自然语言语义真伪，且尚未自动接进V80学习。
3. `writerforge/experience_decision.py` 能把待审经验放在候选／签名许可实验／撤销与负例隔离的受控路径，**不同于**V79–V82内容寻址原著阅读的经验卡。此前二者缺自动可信桥梁。写作不能因SHA匹配就自认已学习。
4. V81另一作品的双臂输出差异已由V84只读审计证明，而两臂没有独立文学质量赢家；这个观察绝不能被转换为训练晋级。

## 2. V85已实现代码：不再造第二套关系网

### A. `writerforge/v85_literary_evidence_gate.py`

- 严格每条假说的 `claim_id`、源书SHA、章次、假说类型、人物ID/事实ID、显式故事时刻、读前知识状态、原文观察锚点与结果锚点、假说/替代解释/可反证条件/不确定性。
- 每个锚点必须含真实已读单位编号、字符起止位置和**内存中原文短引句的逐字符完全一致**；位置/长度/章节/整章SHA不符立即拒绝。
- 原文只用于短时验证；输出仅保留来源SHA、单位SHA、引文SHA、位置及文字解释SHA；**不会**将原著句子、原始假说和新的解释发送给写作模块。
- 复用现有 `FactJournal.temporal_view(...,story_id,as_of_ledger_seq)`。学习前固定global ledger时点；以后录入的知识、角色同名但不是同一作品的关系不得回填过去。
- 当人物知识为`UNRECORDED`、`UNKNOWN`或`DISPUTED`时，保留`UNRESOLVED_OR_ABSTAIN`；不伪造KNOWN或自动补写解释。
- 所有返回状态明示 `literary_semantics_independently_verified=false`、`eligible_to_direct_writing=false`、`skill_promotion_approved=false`。来源先后≠故事真实时序≠文学因果。
- 有界资源：最多80单位、最多6条候选、单锚点8–120字、说明限240字、审计收据原始JSON最多8192字节；非法/巨大输入直接拒绝。

### B. `writerforge/v85_pass_a_bridge.py`

- 对现有R2 LEARN的每个`first_read`事件逐条复核：原著章节SHA、单位SHA、上一个事件SHA、读书次序、`future_source_seen=false`，再校验`seal`是否真实封存对应的**全部**来源单位。
- 禁止把V79早期第一章混合流程改写成严格整章先读再分析。
- 只有PASS A封存成功，才允许在**单独受控**的V85审计里处理模型提出的新结构化假说。历史V80旧模型只给来源单位编号而不含句段位置，不能回填成“精确证据”。
- 默认不写R2。未来如果调用`persist_sidecar(..., explicitly_allow_write=True)`还需要真正Writer权限、同一核验会话的收据绑定和防篡改Hash；存的是新不可变CAS元数据，不替换任何历史R2学习事件，也不解锁创作。
- V85仍不提供Cloudflare原生LEARN专用接口上线的声明。

### C. `writerforge/v80_large_chapter_batch.py`

- 增加**仅显式调用**的`audit_sealed_literary_claims`方法，复用当前V80批次的源文件身份、章节、R2 journal与新桥接器。旧`complete/first_read/analyse/reflection`调用和输出不变。
- 必须传新的结构化证据与已有FactJournal冻结快照才能审核，不能从原来单位SHA的分析自动编造句段锚点；不能用这个审核接口发起DeepSeek付费调用。

## 4. 底层仍未解决的关键问题（明确隔离）

1. **最大的未完成点**：当前生产V80模型输出格式只有`mechanisms/unit`，而V85要求原文短引句精确位置及人物知情/反证字段。新的严格审计接口**不是默认已启用的训练协议**；真实LEARN要在独立的新实验工作流生成该输出，并从可信FactJournal构造知识快照、保留失败和弃权才可端到端验收。不能偷偷对前15章加“通过”标签。
2. FactJournal即便已签收`KNOWN`也只证明一种**结构化断言的记录**，仍需独立核实其原文语义。不应靠模型先创建KNOWN记录、再拿该记录给同一模型的假说自我背书。
3. `story_tick`目前由待审候选给出，V85仅验证类型/范围/现有Ledger状态，**不能自行证明倒叙、事件时间或人物动机的正确解释**。真实文学效果、独立盲评、跨书泛化仍未进行。
4. 单个从R2来源封存到SQLite关系认知的自动映射、跨两个持久库的原子事务及补偿仍未生产验收；不能自称“完整一体化长期文学记忆已经建成”。
5. V85侧车结果默认和永久标记`candidate_only`，不增加Skill等级、不允许经验绕开受信实验权限控制。旧V49`THIRD_STRIKE_FAILED`及第二文学窗口`LOCKED`维持；第16章V83已知失败（错误SHA源代码已修），未重付费完成，第17章也未开启。
