## 2. 新架构已经接进 G / Studio 原有写作流程，不是另起文学模块

新增 `writing_assist._reader_separates_written_and_inferred`（可选，同一个写作模型）：

1. **读者视角请求必须独立**：仅收到刚刚实际写出的整段小说，不能看到先前的章节计划、创作 AI 自我辩护或系统提供的剧情错误答案；只输出有**唯一真实原句**支持的表层动作与读者自行推测的缺失过渡。
2. WF **仅核对 source quote 的真实字节和前后顺序**，机械绑定原稿 SHA；不因出现读者推测自动判定故事错误，不擅自重写任何文字。JSON 不合法或引句捏造就保存原答案和 `INVALID_READER_SOURCE`，不能进入作者判断当作已知事实。
3. **原作者视角**接收注明“仅同一模型读者推测、不是软件裁决”的来源引用，然后**自己**选择 `MOVE_ON` / `LOOK_BACK_NOW`；原 `_ai_decides_when_to_revisit` 和 `_self_edit_one_turn` → V119 / V96 / V114 / V117 / 唯一 NarrativeCore 继续作为事务主人。
4. `AutonomousWriting.run(reader_first_self_review=True)` 只在明确开启 G、`self_edit_rounds>0` 且 `self_edit_timing=ai_decides` 时允许。开启的额外读者调用计入**原有每作业最多 8 次**自主审稿供应商额度，而且在只剩一次额度时优先留给真正的作者决定。失败回看恢复须一并撤销衍生读者收据，不复活废稿。
5. Studio 有默认关闭的“先独立读者复述再作家取舍”控件；开关只调用原后端、不自动强迫作者删稿。V26 Ctrl+1/Ctrl+2 两个续写选择、自动保存、作者丢弃本次草稿、V98/V114/V117/统一图与旧 A–F 不改变。

实验前使用 GitHub 自带只读凭据下载并再次验证原始 #40094106486 的 **451 字稿、原供应商 wire SHA、两次老模型原回复**，没有重新生成同一篇小说。这一次将已写稿交给**同一个 DeepSeek Flash**，但先以完全没有原规划和旧 `MOVE_ON` 的读者角色读一次，再以原作者角色决定。

真实结果：

- 读者阶段有效输出 **8 条唯一原句表层动作／观察**和 **3 条来源前后引句支持的“可能需要读者想象补出的过渡”**；不是 WF 软件产生的文学结论。第三条明确定位：“程九说完‘我留着’后从坐船状态变为蹲在桩边缠绳子，这一位置与姿态转换原文未直接描写。”
- **模型首次真实自主 `LOOK_BACK_NOW`**。它提供的实际原句是“程九已经坐进船里，竹篙横在膝上，脸朝着雾里那声哑喊，没应。”，自己说明：“位置和姿态的转换没有落笔，读者只能自行补足”；它认为这是“留下”选择的关键动作，值得写出而不是敷衍成正常留白。
- 随后的第三次真正写作模型调用给出一份 `REVISE` 局部段落提案，其中实际**由模型本人写**：“片刻后他却又起身跨回岸上，蹲到桩边，把竹篙搁在一旁。”
- **结果未真正落稿**：原 `_self_edit_one_turn` 因模型多出了 `type=json_object` 包装字段，返回 `WF_SELF_EDIT_SCHEMA_INVALID`，旧真实候选 451 字保持逐字不变；**不能把这次叫已成功编辑或文学质量提高**。

本轮模型真实报告用量：**3 次调用，prompt 4,120 tokens、completion 1,480 tokens**；供应商用量并非货币发票，不得自行估算收费。没有调用新审稿模型、重复原训练，也没有把任何输出存作被批准的文学经验。

## 4. 最重要的深层错误：文学意图已经形成，因果字段却写错

对原真实 V119 答复另建 [完全零模型的原 reply 重放 #40109306167](https://github.com/66tyu55/WriterForge/actions/runs/40109306167)，从真正老提供商附件读取原 SHA 及 `03-AUTHOR_V119_REVISION` 原始 wire，未问 DeepSeek，也未修改其替换文字与 trace。

这一阶段只增强**机械格式兼容**：

- 兼容 DeepSeek 官方已经实际出现的一个可证明冗余 `"type":"json_object"` 包装，不接受其他异常字段；raw 仍原字节保存。
- 若模型给出的 `start/end` 实际超出 451 字原稿，但它的 `expected_original` 在源 SHA 锁定原文中**唯一逐字出现**，只恢复真实字符坐标并记录模型错误位置，不推断需要修改什么、不挪动其他文字。实际源码 V119 生成了 **一份来源锁定的私有候选预览**，并非最终采用。

随后原 V96 仍然拒绝，真实原因从第一层的 `WF_SELF_EDIT_SCHEMA_INVALID` 细化为：

`WF96_UNDECLARED_PREVIOUS_CAUSE`

模型给出的 `trace.parent_effect_quote` 填入同一场景里的“我留着……”对白，但本段 beat **没有前一事件父节点**，V96 正确要求 `null`。因此即使纯格式和唯一引句坐标可机械核验，**现有程序不得偷偷把模型的原因引句当成先前确证事件**。真实作品照旧未变，校验红灯原样保留。

[零模型重放、旧原答复、严格私有预览和最终失败原件](https://github.com/66tyu55/WriterForge/actions/runs/40109306167/artifacts/12566001733)。

已改进后续新模型调用的**原技术格式提示**：当 `beat.causal_parent=None` 时，明确告诉模型 `trace.parent_effect_quote 必须是 JSON null`，不得用本段对白冒充以前发生的真实后果；也提示当模型字符坐标无法正确计算时，应逐字给出唯一源引句（由程序自行定位坐标）。这只是减少 **下一次**结构字段错误的机会，不等于重新把本次历史坏答复洗成成功。

## 5. 真实文学评价：结论仅限于一个样本

**相比三次以前全部 `MOVE_ON`，这次独立读者阶段让同一个 AI 真正产生了 `LOOK_BACK_NOW`，并独立写出针对真正位置断口的可读修改句。** 这比仅重复告诉模型“看看哪里错”更有意义，但它仍只是**单一场景正向机制证据**：

- 还没有一份**通过全部 WF 严格源/因果/时态门槛**的真正修订后作品，更没有匿名读者原稿 vs 修改稿的文学盲评。
- 不能宣称 WF 已训练出更聪明的模型。仅是同一模型在有来源可核的**流程**里有一次不同的文学自我判断；更多不同题型、不同原稿与多模型复核才能判断能否稳定泛化。
- 初读读者的 3 条“可能缺失过渡”仍是 AI 的**推测**，哪怕真实引用均可核实，也不能自动晋级世界事实、人物动作图或长期文学规则。
- 完整的 G/Studio 端到端和这次真实单场景探针是**不同证据等级**：G/Studio 这轮由无模型全量回归保证结构通路，真实模型只在旧单篇原创 451 字范围完成独立读者—作者—改稿提议，不冒充两章文学长程修订验收。
