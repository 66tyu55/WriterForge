# WriterForge 0.V｜物理关系来源事务：从“绳结还是不是系着”到可执行的 HOLD 与修复契约（2026-10-25）

**范围：** 仅 `refactor-unified-scene-delivery-audit`。这是 0.U 真正双轨反例的底层工程延伸，不是新文学训练，也不是另一个 memory/model。主线 V26/V98/V96/V114/V117/V119/V122/唯一 NarrativeCore 保持原职责。**无新增真实模型调用；不动 main、Railway、R2 原著或 Canon。**

## 证据从哪里来

- 已签名的真实 B 第二段：“绳结还系在木桩上”与“只是绳子被人从桩头解下来”。这两句的原始 DeepSeek 提供商回答、上下文与 SHA 见 [首次真实 A/B #40163959949](https://github.com/66tyu55/WriterForge/actions/runs/40163959949)。[最终同作者复读 #40165586323](https://github.com/66tyu55/WriterForge/actions/runs/40165586323) 中作者仍选 `MOVE_ON`；文学决定不能假造为“作者已修复”，更不能重写旧模型原回包。
- 此处有**两种不同的不确定性**：① 谁在夜里动了绳，动机何在，作者可以保留悬念；② 同一叙述时刻这条绳的绳结究竟是否还系在桩上，哪些部分在不同位置，必须有来源才能让后文安全引用。② 不代表程序已证明文学错误；可能是两根绳、两端不同、叙述中省略了明确时间。
- WF 只用原始实际小说的字面锚点产生待审候选：`source_start`、`source_quote`、引句 SHA、整段 SHA、`item_literal`、`contact_literal`、`ATTACHED/DETACHED`、`EXACT_LITERAL/POSSIBLE_ALIAS`。**不会自己给人物安排解绑动作、裁断别名、创造正文或决定什么写法有美感。**

## 必须过的对照和失败测试

1. 真实 B 第一/二段来源一致、原句偏移与引句 SHA 字节相符，能产生一条未证物理关系配对。
2. 完全相同物品/地点，不因补丁而放宽 source SHA；可能为局部别名时只列可能别名，不记为相同事实。
3. 明写**先系后解**、**后来解绑**不应 HOLD；**两根不同颜色/编号的绳**、**只松开自由端**不应被归成同一整体。
4. “猜还系着”“听说有人解绑”“不知道谁动了绳”，不是叙述者确定物理事实；不得把主观推测晋级正典。
5. 非绳索例子（如铜牌挂在门钩上随后声称已摘下）应由相同关系解析器发现；不能只靠 `绳结` 关键词补丁。
6. V114 原有 reducer、V117 原有签名和统一 graph 对新来源证据不得报虚假 success；旧不确定风险只能随**匹配的后文关系声明**继续生效，写无关剧情不被无限阻断。
7. 在 V119 测试模拟“作者改了无关句子”，前后疑问仍在，必须私有 HOLD；模拟作者精确改掉不一致来源后才会机械消除该风险，但这仍**不是已发生的真模型文学成功**。
8. 有不匹配 SHA、非唯一引句、伪造之前来源收据、源下标错误时，不能静默接受/重试。

## 尚未宣称成功的部分

- 这套审查不能处理所有依附、容器、所有权、动作语义、叙述时间的隐含逻辑，也不能判断作者心理/悬念好坏。
- 真实作者之前的 `MOVE_ON` 不能抹掉；新代码仅有零付费源码级验收，**没有真正成功的“作者自选 V119→修改→下游重写”新增模型证据**。
- 修改时态的跨度目前限实际来源窗口与紧邻签名源，未证关系不能变成全章/冷记忆里的权威关系卡。
- 正式跨更长章节、多角色物件关系与真正人类文学盲评，仍是独立后续验收。

**继续工作的原则：** 任何工程红灯只修其真实原因，不通过增加词表凑绿色；反例要保留。若一项修复反复失败，回原底层梳理，不允许对同一 `《潮簿》` 再付费问第三次。新真实模型文学实验需换原创题，依旧由同一创作模型自主创作全部正文。
