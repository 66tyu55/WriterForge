# WriterForge V121 — 人物归属检查与创作提示预算

日期：2026-10-22
开发分支：v121-actor-bound-continuity-prompt-budget
基线：V120；生产 main 未修改；Railway 未部署。

## 问题与原则

旧 V116 的右臂检查是“此前有人右臂受限”加“当前正文出现右手挥剑”，这会把唐蜃的正常动作错算成沈砚的伤势违规。写作提示也存在风险：V118 的可选路灯和 V120 的未兑现计划提醒追加后，可能触及既有 10,000 字符提示上限。思考计划不等于已写事实，模型自评不能变成事实凭证。

## 已完成修改

1. writerforge/v116_state_delta.py：只从结构化状态单元确认受伤人物；根据本句明确的动作主体进行右臂检查。沈砚使用已受限右臂仍被拦截，唐蜃用右手不会误伤主角。未明确主语的“他右手挥剑”进入待审，不强行归属。否定、仅尝试、对话、梦境不能被当成实际挥剑。医治来源与动作人物须对应，无法确认则待审。

2. writerforge/v117_continuity_trace.py：保留强冲突 blocked，同时新增 state_review_findings 与 needs_review，把有根据的硬拦截和代词歧义分开。实际写作调用向预检传入 cast。

3. writerforge/writing_assist.py：新增 _prepare_guarded_turn_packet。真实前文状态、时间因果与当前回合约束先占用预算；候选章节计划、V120 依赖提醒和 V118 创作路灯按剩余容量选择，记录实际是否送入模型。如果硬约束自身超出上限，调用模型之前明确失败，不截断事实。实际提示哈希与取舍进入既有 V96 候选证据。

4. writerforge/v118_lamp_scheduler.py：加入 max_prompt_chars 可选参数。压力下先省略文学技法问题，再减少重复性软提示。未真正输出的技法不计入下轮冷却，仍有签名决策凭证。核心时态状态不由软提示承载。

5. writerforge/v119_revision_transaction.py：手术式局部修订支持显式 cast，避免对手动作误拦截；新出现的人称不明写入 new_preflight_review_flags，保留原文与人工审查边界，不自动进入正典。

6. tests/test_v121_actor_and_budget.py：覆盖敌我角色切换、对话与梦境、否定与打算动作、真实伤者的硬检查、具来源的恢复声明、模糊代词、零预算无冷却、只保留硬约束、局部修订新增待审标志等场景。旧 V118 静态调用位置测试也更新为实际行为检查。

## 风险与交接

V116 仍是有限的中文动作识别，并非普遍语义理解。未知主体应保留未知；不应为了覆盖率强加主语。原有火髓果等资源检查还使用窄词形与部分历史特指人物，需要之后做独立反例测试。可选文学提示与硬性状态有不同优先级，不能让模型解释或候选大纲替代真实正文证据。已研究的 Graphiti、LangGraph、Mem0、GraphRAG 等高 Star 项目没有在 V121 新增依赖或付费运行。

下一轮建议围绕多角色物件转移与代词消歧扩展来源核验，做固定预算、同模型千字写作盲测前先封存测试协议与失败标准；未得到新许可，不调用付费模型。
