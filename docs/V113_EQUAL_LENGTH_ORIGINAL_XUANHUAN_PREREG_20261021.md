# WriterForge V113 · 实际字数控制的玄幻追逐打斗三臂盲测预注册

时间：2026-10-21。**此文件和源码必须先于任何 V113 付费请求提交。** V112 真实四次调用及其全部私有R2原始答复保持不变；旧15章学习与V49失败、第二文学窗口LOCKED不变。Railway不参与。

## 目的与唯一题目

用户同意继续根据 V112 的**实际原文**比较WF与开源写作技能，而不是一章章盲训。V112三臂正文 1472/962/1588 个含标点Unicode字符，实际长度差39.4%，不符合公平排名。V113重新创建新的独立实验，努力约束文字长度并审视长短与叙事质量关系。

唯一共同用户问题，逐字不改：**给我一个追逐打斗的玄幻1000字**。

三个独立组：
- **WF_SINGLE**：旧WriterForge `AutonomousWriting.run(draft_mode='single')` 真正章规划（最多650输出tokens）与一次完整正文（最多2600输出tokens），用仅有中性软件兼容样本的玄幻已发布Xuehai入口。没有注入以前15章真实阅读经验。
- **GITHUB_STORYTELLER**：同一官方 `deepseek-flash`，给它原版MIT Storyteller `SKILL.md`（旧V111固定sha）作为独立指导，正文最多2600输出tokens，不能读取WF技能或过去WF草稿。
- **BARE_DEEPSEEK**：同一官方 `deepseek-flash`，不加载文学Skill，仅共用自然写作及JSON输出合同，正文最多2600输出tokens。

唯一改变（对三组**完全对称**）：在每组共同正文系统指令里更清楚要求“写到950—1030字符安排自然收尾、最终900—1100字符”，不强制统一故事角色、地点、招式、人物命运或结局。不靠强加固定情节模板达到对齐。实际字数仍以供应商最初生成的未经删改原文为准，不截断、不自动续写、不重新抽样。

## 真实公平性门槛

- 全部三稿正文Unicode码位含标点必须在 **900—1100**，同时三稿最大长度差 / 最大稿长度 **<=10%**，否则禁止排“文学第一名”，仍分别审稿留负例。
- 同一模型名字、问题文本、正文输出预约2600tokens。WF多一次章规划650tokens，实际输入system/prompt与技能组不同，所以仅是**工作流整体可观察对照**，**不是等计算量、等成本或WF学艺提升的因果实验证明**。请求数分别2/1/1，预算总上限4请求、8450输出tokens预约、保守150000tokens。
- 禁止“为了等长”给WF提供Storyteller原文；禁止任何外部AI在生成中或生成后审稿、给答案、修改故事。返回不合JSON或偏离字数则保留原稿，零重试。
- 独立匿名全文先保存私有R2，揭盲对应另存owner-only CAS。提供GitHub artifact以匿名文件交给读者，全文与哈希冷恢复；不能让GitHub CI PASS成为“文学PASS”。

## 核心文学对照标准

每篇固定审：①追与逃角色的愿望、时空距离、场景转移和速度；②每次打击和防御真正使哪一状态改变，是否无证飞跃；③玄幻能力的发动条件、实际限制和资源消耗；④受伤、地形破坏、第三方伤害有没有影响后续决定；⑤打斗中视角、人物语言、节奏是否自然，是否密集堆叠招式或事后补充万能反转。以全文实引和首疑点Unicode字符坐标为证；文本留白、幻术或未知不能直接定为硬错。

只有一题一次样本，不得以单次输赢定WF技能等级。评分应先匿名看全稿；不给任何AI自动颁发“进步”。最终报告特别说明V113使用**中性接口样本，尚未调用历史15章知识**。
