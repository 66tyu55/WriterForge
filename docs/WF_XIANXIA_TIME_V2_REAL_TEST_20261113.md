# WF 修仙时间参数 V2 — 真实角色写作对照（冻结协议）

日期 2026-11-13。实验状态：尚未启动本地模型；按用户要求，只修正时间参数设计，不改造整个 WF。

## 为何重设计

V1 缺陷：世界日与身体经历日相等、没有洞府时间参考系、人物离开主角视角容易“冻结”、修炼累计天数被误当突破的充分条件。V2 分离世界小时、人物主观小时、实修小时、纪元历史与境界资格；数值全部有单位、参考系、更新规则和可明确修改的单参数路径。

**禁止把单元测试通过当作作者真的遵守时间规则。** 先验收纯时间引擎，再验收真实正文。

## 冻结测试人物与世界

角色随机种子 `20261113`，身份“灵田佃户”，性格“谨慎却倔强”，角色 ID P001；洞外陌生守夜人 N001。时间 1000 世界小时开始，1008 小时洪水到达。P001 已实修 6 主观小时，在洞中再修炼 6 世界小时；需要累计 20 主观实修小时才有资格尝试突破二境，二境可用护堤术，但不保证突破或救堤成功。N001 同时在洞外独立工作。

## 同模型三组

- baseline：同角色、危机、六小时修炼，**不给精确仙侠时间参数**。
- rate1：洞府 1 主观小时/世界小时；结束时 12 实修小时，成功突破不符合前提。
- rate3：其他一切相同，只把洞府换为 3 主观小时/世界小时；结束时 24 实修小时，可以尝试突破，但有权失败或不尝试。

自动生成的故事和事件表都要保留完整原始回复；不能把事件表算对当成正文自然合理。三组使用同一 Qwen2.5-3B、同一 seed、同一生成 token 上限，**并不保证输入 token 相等**；因此这只是一次观察参数行为的实验，不是有统计显著性的文学质量 A/B。

## 预注册判定

1. **规则有效（程序）**：单改洞府倍率，同一“修炼后成功突破并施法”的行动链在 rate1 必须拒绝、rate3 可以接受；世界时钟和洞外守夜人时间不能跟着倍增。
2. **规则影响小说（模型）**：rate1 与 rate3 的真实写作选择应出现与时间资格一致的不同情形，或者有可信的其他选择且不造成矛盾。纯照抄时间参数不算改变故事。
3. **时序可靠（模型）**：生成的记录必须从同一六小时闭关开始，时间推进与独立角色经历可重放；正文不能写十年闭关却报六小时，也不能在未突破时施法。
4. **文学自然**：人物允许犹豫、救人、畏惧、失败，洪水按时间独立推进；不得为了过关强行让角色升级。无独立人工盲评时，文学质量结论只写“未证明”。
5. **停止条件**：如模型未受约束，保留全部失败；不换提示词或重复调用刷通过，明确指出是参数模型不足、模型遵从不足，还是正文/事件表不一致。

**所有场景为原创测试，不以原著文字作训练。没有微调任何模型、没有对 WF 学海库/R2/Canon/生产代码写入。**
