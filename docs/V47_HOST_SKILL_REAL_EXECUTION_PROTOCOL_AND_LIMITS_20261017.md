# WriterForge V47｜真正可由宿主调用的 Skill 全流程——工程完成、文学尚未验收

日期：2026-10-17。V47基于V46 Draft分支，保留此前V35—V46所有原始失败、R2历史、文学争议和先前审计SHA，不回填或修补旧证据。

## 本轮目标

针对V46发现的缺口：正式SKILL.md只有文学架构约定，标准CLI没有可恢复的盲读→深读→未审经验→同题A/B写作→自评会话。V47直接添加writerforge/skill_host_session.py并接入原CLI和SKILL.md操作说明，实际复用OriginalStudy、SceneLiteraryStudy与VerifiedWritingFlow，而不是另做一个旁路模拟。

## WF实际有权控制的5个阶段

1. FIRST：SourceStudy真实入库并保存SHA，进入LEARN；只向单宿主暴露固定盲段；宿主给出的首读JSON经WF原有lock_first_read锁定。无后段泄漏。
2. CLOSE：只在首读已锁定后暴露全段；原有SceneLiteraryStudy验证每条原文确切引文；从已存分析取第一条假设，自动保存未验证经验候选。**生成解释的仍是所配置宿主，非WF脱离宿主独立语义推理。**
3. BASELINE：WF正式VerifiedWritingFlow.prepare生成相同新题的无经验创作请求，宿主生成正文，原版save_candidate实际存候选但不接受为正式作品。
4. LEARNED：同一model_id的宿主收到WF从冻结经验自动提取的操作问题/替换思路，不接收原著原句，再经原有save_candidate保存作品。两条创作指令确实不同，不保证艺术质量变好。
5. SELF_REVIEW：对真实两篇候选引用明确存在的短句并记录失败，**同宿主自评绝不算独立批评**；随后会话 COMPLETE，不得重开旧答卷。

接口：skill-host-start / skill-host-next / skill-host-submit / skill-host-status（宿主拥有命令执行能力时可按严格阶段走）；新增单命令skill-host-run-local则由WF自身循环调用**同一个明确配置、已运行的127.0.0.1本地语言模型**，自动完成各阶段，无需考官逐个填写答案；模型不可用就停止。所有会话在现有WriterForgeDB里持久，写前后都能回读与恢复。模型身份只是字符串约定，没有密码学服务端签名。

## 真实验证与结果

- 真实Python/CLI路由和SQLite/Xuehai/SceneLiteraryStudy/VerifiedWritingFlow参与单元测试；使用可信的《西游记》第一回仓库原著测试段，不是空白对象。
- 本轮测试的宿主JSON和小说文本全部是**明确标注合成的协议测试夹具**。这验证会话转移、原文锁定、引用存在、SHA一致、同模型标识、保存候选与重启恢复；不是完成了真实AI文学训练。
- 测试还验证了远程HTTP模型地址被禁止；没有本地模型时不得使用云端备用模型或事后补写答案。
- 旧版全部100回原著学习、文学经验V38角色争议和V45误把无因果场景当成成功的失败记录保持独立，绝不能用这轮测试改写。
