# WriterForge 修仙时间规则 V2：参数重设计与五次真实写作测试最终报告

日期：2026-11-13。开发分支：`feature/wf-xianxia-time-rule-20261113`。性质：**实验性、独立可拆卸 Skill**，没有改动正式写作引擎、唯一 XuehaiStore、R2、Canon、Railway 或 main。

## 1. 此前错误与新参数设计

V1 的核心缺陷：世界经过的天数被机械等同于每个人的年龄与修炼时间，无法表达洞府内外流速，主角视角之外的普通人没有独立持续的时钟；单一修炼门槛加“成功”不等于修仙世界的通用规律。

V2 用显式、可计算的字段代替无语义参数：`world_clock.hour`（世界小时）、`time_frames.*`（主观小时/世界小时的精确有理数）、`actors.*.age_subjective_hours`（身体经历小时）、`actors.*.cultivation_subjective_hours`（实际实修小时）、独立的`advancement.min_cultivation_subjective_hours`（本原创世界的最低尝试资格）、`era_history`（纪元标签，未知年代不造数）和`technique.latest_world_hour`（事件截止时刻）。所有人物同时随世界时钟推进；未观察到的 NPC 不会因此停止衰老，也不能自动获得修炼功时。

固定随机种子 `20261113` 选中一名“谨慎却倔强的灵田佃户”，与河堤守夜人共同处于洪水将至的独立故事。世界小时 1000→1006，洪水 1008 到来。两组仅修改洞府流速：×1 对应主角新增 6 主观实修小时、累计 12；×3 对应新增 18、累计 24。洞外守夜人两组只经历 6 小时。最低成功突破资格为 20 主观实修小时，**达到资格不保证突破成功，也不保证护堤成功**。用同一固定“尝试成功并用二境术法”行动序列，×1 必须拒绝、×3 可接受；世界时刻与守夜人经历时长完全相同。

**机械代码验证**：[Actions #43390894665](https://github.com/66tyu55/WriterForge/actions/runs/43390894665)，V1 历史回归 11/11，V2 参数、单变量变化、作者摘要和输入检查 24/24，合计 35/35 PASS。**这些都不是小说质量检验。**

## 2. 真实模型试验一：原始完整参数输入，作者行为未改变

[Actions #43389602974](https://github.com/66tyu55/WriterForge/actions/runs/43389602974)：同一 SHA 锁定的 Qwen2.5-3B-Instruct Q4_K_M，本地 CPU 推理。baseline、×1、×3 各一次原始作者输出，三次 JSON 均有效，三次机械时间记录均可重放。

但是三次小说都是极短的开局、犹豫或“需要尽快行动”，`time_events` 三组全部只有预先规定的闭关 6 小时。**没有实际突破、救援、对洪水的应对或行动代价**。虽然 ×1 与 ×3 规则数字不同，但没有显示对作者下一步行为的约束作用。模型甚至把角色职业连写成“灵田佃户灵田佃户”。按预注册标准：**实际写作 FAIL**，没有把这个问题算作引擎通过。

## 3. 真实模型试验二：只给计算后的可行条件，作者行为改善但因果依旧未通过

针对上面*已经看到*的失败，追加唯一一次透明的探索性方法修正（不是重新宣称盲测）：`scripts/time_bridge.py` 从 V2 已执行状态生成简短作者窗口，说明世界时刻、剩余世界时间、角色实修小时、是否具备尝试资格、独立 NPC 已经过的时间。作者不再接收 1700 字的底层 JSON，也不用同时填写事件账本。

[Actions #43390894621](https://github.com/66tyu55/WriterForge/actions/runs/43390894621)：同一个本地 Qwen2.5-3B，种子 `20261113`，同样 2048 completion token 上限，同样角色和危机，只改洞府倍率，两个真正的原始小说正文输出。

| 组别 | 小说正文字符数 | 原始小说实际表现 | 审核判断 |
|---|---:|---|---|
| ×1 | 878 | 主角确认修炼尚不够，离开洞府去看堤，却反复犹豫和折返；没有确定的救援后果 | 比 JSON 版有更多行为；情节/后果仍弱 |
| ×3 | 744 | 洞外守夜人进入洞府把主角拉出，奔向河堤，洪水冲往村庄；出现真实失控后果 | 比 JSON 版有实际事件，但不体现已满足突破条件对选择的作用 |

**致命未通过点**：×3 组叙述让原本不认识主角的洞外守夜人似乎知道主角的洞府及修炼突破状态；违反角色认知来源。×3 组没有表现“已实修 24 小时、可尝试突破”的判断与行动，二组写法差异不能归因于时间倍率本身（模型使用相同种子，并不保证小样本反事实因果识别）。×1 组重复“还需更多时间”，却没有写出一个完整的行动代价。二组也均缺乏独立读者的文学判定。

第二轮说明把参数转化为简短的**当前可行条件**可改善生成篇幅和行动具体性，但仍不足以证明“参数真正成为自动作者的因果创作规则”。按停止标准：**作者行为因果转化未通过，不再重试。**

## 4. 失败根因归属与下一层应做什么

- **参数底层：阶段性 PASS。** V2 的单位、参考系、各人物时钟、实修与真实世界耗时区分、正反约束均准确响应单变量改变；没有必要因作者失败而删除这一已经有效的纯时间引擎。
- **参数到写作：FAIL。** 原始参数表让作者复读；改成可行状态摘要后，作者能行动却没有可靠地以时间条件改变具体决策。
- **角色认知与独立世界：FAIL。** 时间并不能代替“谁知道什么、谁在做什么、他们为何行动”的关系状态；它们应继续保持独立能力，不得塞回时间 Skill 或给作者硬编码固定动作。
- **实验解释受限。** 本次测试只是一个原创随机角色、两组作者输出与一个 3B 模型，无独立人类金标准、无多场景盲评；仅验证输入接口与个别故障，不是“文学训练”或全原著反推成功。

## 5. 决策

**保留 V2 时间引擎和 `time_bridge.py` 为 SHADOW；停止新增同类时间模块与模型重试。** 原始模型 wire、小说文本、提示、单元测试与所有失败均由 GitHub Actions artifacts 保存。未曾微调权重，未使用付费模型/原著私有数据，未合并到正式 WF 写作流。

未来真正需要检验的写作机制是：**作者自主提出具体行动 → 独立规则判定其在当时时间上可行与否 → 作者选择保留、修订、放弃或承担失败 → 正文落实实际后果 → Commit Boundary 验证变化**。这必须联接既有 WF 的人物认知和事实状态，但不可由时间规则替作者决定剧情，也不可为通过验证写出固定模板。只有在“自然语言选择 + 已建立人物认知 + 具体时间成本”三者同场通过时，再谈生产接入。
