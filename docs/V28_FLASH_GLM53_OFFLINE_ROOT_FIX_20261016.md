## 2. 区分可证实的问题和文学假说

**现有代码能直接确认：**

1. v4 的 Critic 虽未收到“技能组”的标签，但与 Planner 使用同一 Flash 模型，并收到了原著正文的 `source_context`。这并不符合强隔离的“纯原创质量”评审：可能奖励与参考原文一致的叙事选择。去掉原著输入后仍不能称真人盲评。
2. 原审核记录中的长度控制仅排除了超过15%的一项混杂；没有作者身份/场景/任务多样性重复样本，同一组分数不等于迁移、记忆保持或稳定优越。
3. 评价短理由的原著/草稿重合检查原先仅针对超过55字符且全段相等；18—55字符的原文连续节选可能留存在轻量报告内。它不是完整隐私或语义剽窃检测。
4. `reverse_cloud_ab.py` 返回受限模型评审，不会自动把负向项、阈值缺口或未复测情况导入候选证据账本；现有 `ReverseCraftCoordinator` 的学习状态机与这条真实云端 A/B 尚未形成统一晋级证据。

**只能作为待验证文学假说：**

- 带职业经验的感知+行动代价可能帮助因果可信度，但本轮选中宿主预置机制，并非自动学出的新核心。
- 信息释放 87/100 是弱项；审评指出悬念线索不足，未来应以新场景检验“先导线索与延迟解释”，不是直接给所有作品强塞该机制。
- v3 的负分差可能来自提示词机械化/机制冲突；v4 的正分差可能来自模型与随机生成差异，不得把任何一种推测写成已证实根因。

## 3. 本轮底层代码修复（无真实付费调用）

- `writerforge/reverse_cloud_ab.py`：未来 Critic 的输入**只有共同创作任务及 A/B 匿名稿**，不含原著 `source_context`；新报告加 `critic_prompt_original_source_prose=false`，旧 R2 原样保留、不伪造历史独立性。
- 该模块中的有限短评脱敏改为检查 **18 字符及以上连续重叠**，包括中文短节选；保留“短引文及语义改写不可完全检测”的已知边界。
- 新增 `writerforge/reverse_ab_candidates.py`：只接受内容哈希与完整回执匹配、原著未流入 Writer、长度及整数评分自洽的**既有 A/B 抽象报告**。把模型低于90的维度、负分差记为 `CANDIDATE`，机制仅保留宿主允许的 ID；原著与草稿原文、模型自由短评都不会进入新 SQLite。首次真实记录仍标 `SINGLE_MODEL_UNCALIBRATED`；跨场景闭卷证据0；遗忘 `NOT_TESTED`；晋级永远 false。
- 专用本地 SQLite 以真实 R2 回执哈希为主键、128次证据硬上限、事务写入、同回执重复导入不加一、冲突拒绝；不修改已有 R2 不可变快照或真实书库。
- 新增离线测试覆盖新账本的哈希伪造、长度伪造、原著污染、未知机制、同次刷证据、旧版批评者独立性不可追认，以及未来评论不得收到原著。

这仅是**证据安全和实验方法底座的修复**，没有宣称提高了故事文笔、解决所有语义复制、完成实际闭卷迁移或把新候选上传到私有 R2。
