# WriterForge：锁定真实第一段的文学 A/B，负迁移与回退

2026-10-23。唯一分支 refactor-unified-scene-delivery-audit。核心目标仍是 WF 自己写小说，读真实正文发现文学逻辑、人物自主选择和场景效果的缺陷，再对写作行为做最小改进，不加独立记忆。

## 原因：旧实验中的 4/4 不能证明新提示普遍更好

旧 [四组实际文学 A/B #39964830150](https://github.com/66tyu55/WriterForge/actions/runs/39964830150) 固定同一故事、章节/事件模型计划和同一 DeepSeek Flash，但两臂各自产生了不同的**第一段正文**。新推进提示只加入第二段，然而第一段随机变化本身就可能影响第二段。这一关键混杂没有被旧盲读消除。

## 本轮更严格的真实稿实验

[真实同第一段 A/B #39971705331](https://github.com/66tyu55/WriterForge/actions/runs/39971705331) 对全新世界的剧情（镇上封桥）、高潮（洪水开闸）、恐怖（东湾灯塔）三类，各自复用旧 run #39968891775 已封存的 **同一段真实 DeepSeek 原始 model JSON**，同一章节/事件计划，保留已有 V114 物件、时态和统一 THREAD 图。两臂只为**第二段**各调用 DeepSeek Flash 一次，每请求 max_tokens=1450。三类共 6 个新的真实提供商请求，零自动重试。每类两臂均完整生成，原 provider wire、真正原稿、源校验记录、W1/W2 匿名阅读文件与独立的揭盲映射在本轮 Actions artifact 中。

虽然控制了真实第一段和计划，新第二段仍随机采样，新提示还增加输入 token；每类只有一对。不能把它称为统计显著的文学水平证明。

## 回退与底层保护

开发分支 writerforge/writing_assist.py 已将 continuity_guard 的默认 literary_progression_mode 恢复为 baseline。想测试新方法时可显式选 source_progression，不按体裁名字硬编码，也不作为默认大纲律令。原独立物件、知识、长段重播以及因果来源约束继续存在；提示不自动改稿、不写 Canon。

另修了上一轮揭示的实际调度问题：旧因果提示和新可选文学提示分开分配预算、分别签名与记录真实送达，文学建议不会把原来能送达的硬/因果内容一起挤走。该修复通过完整 CI #39967843246 的 1,448 项验证。恐怖旧 W2 的 975 codepoints 正文已在统一模式内有限保存并标长度待审，旧 V96 950 字符规则未改；原来源经零模型调用复验 [#39970808206](https://github.com/66tyu55/WriterForge/actions/runs/39970808206) 两臂完整保留，不篡改最初红灯。

回退默认后最新全量 [GitHub Actions #39973669036](https://github.com/66tyu55/WriterForge/actions/runs/39973669036) **1,457 tests run，4 skipped，0 failures**。旧生产 main 未修改，Railway 未部署，历史 Atria 七类原始失败继续保留；已完成付费工作流改为只有手动触发。

## 真正应该继续研究的文学问题

剧情应让新信息改变选择，却不能凭残损领料单断言造假；高潮必须保有可信倒计时、可行动的冲突与实质风险，而不是任意增加机械设定；恐怖要保持空间和观察限制产生未知，而不是为了每段有新反馈过早解释。人物仍可克制、犹豫、失败或放弃预写目标。下一轮必须以新作品的跨章实际连续性与独立盲读来验证，而不是只看格式通过或模型自报效果。

小样本失败和正例均应留在原始报告，不能把前次 4/4 作为已经学会文学创作的结论。
