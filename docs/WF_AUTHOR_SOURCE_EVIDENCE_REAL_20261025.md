# WriterForge 0.R｜原作家说“前章早已写过”，必须区分原文证明、未知和文学留白（2026-10-25）

**状态**：仅开发分支 `refactor-unified-scene-delivery-audit`；没有写主分支、Railway、R2 原著/Canon、没有新增平行记忆库或审稿 AI、没有重复 15 章文学训练。该功能是**单一既有 G/Studio reader-first 机制的来源归因增强**，不是新的文学评分者或逼迫模型认错的程序。

## 一、为什么需要这一步

真实戏楼小说原稿的“赎身票据”在更早签名原文是**江遥衣袖里**，下一章由 DeepSeek 自主生成时却说票据已经在**后台旧箱底的戏服下**。此前真正的 [双原文读者复盘 #40151857245](https://github.com/66tyu55/WriterForge/actions/runs/40151857245) 找到了这个跨章来源差异，并输出三条带原句的独立读者推测；同一个作家模型仍回答合法 `MOVE_ON`，并把“前一章已经交代藏处”当作理由。**文本有两个位置事实，不等于文本真的写过中间转移**。但作家省略交物动作有时是有意义的文学留白，所以绝不能仅因没有明写而强制修订。

原始不带归因的模糊解释和错漏来源均保留在 [原始七次真正写作+自审 #40110957161](https://github.com/66tyu55/WriterForge/actions/runs/40110957161) 与 [后来的两次真正独立双原文复读 #40151857245](https://github.com/66tyu55/WriterForge/actions/runs/40151857245) 里。旧直接作者 `MOVE_ON`、旧 `source_sha256:null` 的 `INVALID_SIGNAL` 永远不能变成模型此前已经给出正确来源事实。

## 二、已经实际接进原有写作中枢的来源归因

在原 `writerforge/writing_assist.py`：

1. 新增 `_validate_author_prior_source_claims`；在作者决定函数 `_ai_decides_when_to_revisit` 上增加可选参数 `earlier_source_for_attribution`，**只有收到真实原文 SHA 对应的独立读者跨文本意见且确实拥有对应的更早已写文本**才启动归因。这个前史可以是当章上一段 V96 原文，也可以是读取自唯一 V117/NarrativeCore 的签名前章；不能说当章上一段“已经签过 Canon”。
2. 写作模型仍**独立**选 `MOVE_ON` 或 `LOOK_BACK_NOW`，不会因为读者指出疑问就强制改稿。同时针对每条已有前后原文引句来源提出 `source_attributions`，每项含 `link_index`、`basis`、`prior_transition_quote`、`literary_reason`：
   - `WRITTEN_WITH_QUOTE`：AI **自称**先前文本已经写出了转移动作，必须提交唯一真实旧原文引句；WF 只核对哈希、字面重复/偏移。**引句确实存在仍然不能证明它的语义就是那个转移**。
   - `UNWRITTEN_OR_UNKNOWN`：AI 认为原文没有明确交代或无法判断，`prior_transition_quote=null`；允许继续写。
   - `INTENTIONAL_ELLIPSIS`：AI 认为这是刻意的文学留白，`prior_transition_quote=null`；允许继续写、但留白并不会自动成为已发生的物理状态。
3. **机械拒绝伪证**：所给的前史 SHA 与读者原句对不上、旧原句不存在或不唯一、前后问题非真实来源，直接拒绝调用模型；模型后来声称“明写”但给假引句，只拒绝它的**证据资格**，不伪造一个新文学决定。若其“已写证据”仅引用了读者提出的**原有持有状态**，回执为 `PRIOR_STATE_QUOTE_NOT_TRANSFER_PROOF`，不能升级成“已核实转移”。格式不合法、漏写来源归因则明确报告，不能默认为所有问题已解决。
4. 不添加新的 model calling loop，读者与原作者归因仍消耗**原 G 单作业最多八次自主审稿请求**中的既有次数。只有明确提供有效早期原文时，原作者同一次判断允许最多 1,150 个输出 token，而旧普通作者判断仍为 600。原始模型 reply 字节单独保存，不由宿主替它写 `literary_reason`，不将来源猜测晋级 Canon 或小说事实。
5. 该来源归因被并入同一 G 已有的 `self_edit_moment_receipts`、`turn_evidence`、章级收据，而不是新建模型、数据库、文学知识模块。原 V26 两候选、V98 滚动构思、V114/V117 状态、V119 精确修改、同一 NarrativeCore 热/暖/冷来源、废稿原样保留和作者手工取消功能不变。Studio 原有**默认关闭**的读者先行开关说明了来源归因范围和可能的 token 开销。

## 三、用同一旧真模型实际验证：1 个新增 DeepSeek 请求，原文不重新生成

[本轮真正新官方 DeepSeek Flash 文学决定 #40153456601](https://github.com/66tyu55/WriterForge/actions/runs/40153456601)

本轮额外模型请求 **1 次**，不是新造三个模型读者，也不是重新训练旧原稿。此前历史真正 G 七次 provider wire + 前史签名 + 前次读者/作者两次 provider wire，在本次付费**之前**严格哈希核对并只读复用，老 `MOVE_ON` 和它的失败理由没有被修改。新的模型作者请求也只由原来的 `deepseek-flash` 输出，最高1次、最多1150 output tokens，不重试。源原文和原模型答复保存在 [真实提供商原始 wire、来源声明及收据附件](https://github.com/66tyu55/WriterForge/actions/runs/40153456601/artifacts/12583830221)。

同一个原作家模型的完整来源判断结构通过核验：
- **`INTENTIONAL_ELLIPSIS` 两条**：它说“衣袖→旧箱底的票据转移”是自己刻意省略的动作，使旧箱子成为江遥重返戏楼的动力；并称“三声鼓→第四声鼓”的连接是节奏留白。**请注意：这是原 AI 自己主张的艺术设计，不是源文本已经写出票据移动的证明，更不是 WF 通过了现实物件状态验证。**
- **`UNWRITTEN_OR_UNKNOWN` 一条**：它承认先前只写宋易“握着后门钥匙”，没有写挂回或揣进腰间；后来“解下来”的动作带有不够稳妥的空间/时间接续，不能说早期早已交代。
- **`WRITTEN_WITH_QUOTE` 零条**：它这次没有伪造一句“前章明确已写出转移”的引文，所有来源归因都明确归类。新模型原始答复确实带 `type=json_object` 包装，但之前只允许这一种冗余标记的严格兼容，原 raw 继续留存；原 SHA 由模型主动正确提供，没触发缺失 SHA 修复。
- 更关键的是：**同一作者这次真的选择 `LOOK_BACK_NOW`**，而且目标**不是**票据移箱，而是新正文这句江遥突然“把重心全压上去，板缘一翻，撞栏”让她此前“谨慎试探裂板”的性格和动作因果显得不够自然。她应该有准备地试探再冒险，跌撞代价才更有力量——这是**模型自己提出的文学理由**。

**真实结果的边界**：真正合法 `LOOK_BACK_NOW` ≠ 已修好小说。这个一次性实验未调用 V119 修订模型，所以**新正文字符变化 0、完整源锁改稿 0、独立文学盲评 0**。需要进一步区分作者审美声称的“有意留白”与有根据的物理世界记录，并真正由原作家写出及校验新的修改稿之后，才能谈文学进步。
