## 本次落实的最小修复（均在既有核心内，不另造 Skill）

1. `writerforge/deepseek_flash_model.py`：仅对 `self_scene_writing` 的真实正文结构，若整个 content 前缀可解析为**唯一完整** `{'prose','trace'}` JSON 对象，而且后面**恰好**是已实测的 2 字符 `"}`，在内存中去除多余尾部包装字符；若正文缺失、JSON 结构错误、任意其他尾串、或角色非写作调用，仍 fail closed。保留原 wire 原貌、原内容/可解析对象 SHA、仅包装纠错的回执，不修改小说正文。不自动发起额外模型请求。
2. `writerforge/v96_causal_turns.py`：`normalize_model_source_citations()` 仅做**可从实际原文唯一定位**的引用规范化，例如去掉错误的单字主语代词、无语义信息的末尾标点；如果模型将以前验证过的较长 effect 截取了一个连续前缀，只在前文原句唯一且完全可回查时恢复完整原引用。严格 `check_turn()` 仍原样复核，小说正文绝不重写。
3. 相同 `v96` 文件的 `review_only_model_turn()`：针对模型自报引用错误、顺序倒置／重叠、对上一段引用无效等**限定**的失败，不再销毁已经按安全 JSON 格式、长度、作者排除词检查通过的真实正文；返回**未证实因果**的候选来源凭证，其 `effect_quote=None`，不可晋级学习经验／正典／人物知情状态。真正 malformed JSON、跨章来源矛盾、重播、用户已设的排除事实仍必须硬失败。
4. `writerforge/writing_assist.py` 继续在同一 `continuity_guard` 入口验收模型两段正文，先存原始生成再验收，串接上面两种**零模型调用**的处理；最终 `v96_turn_evidence.json` 与章节结果保留每项 source citation normalization／model trace review 失败代码，不能把不确定解释成文学质量 PASS。

## 尚未解决的文学核心缺陷

- 搞笑类两段主要在‘验伞骨、验官声’上延长滑稽铺垫，真人巡察使唐蜃没有得到清晰揭示，**格式检查零错误不等于真正笑点实现**。

- 计谋原稿有实际布局、买通守夜人、次日反馈与损失，但计划中的“试探谁知道什么”在正文中仍有推断跳跃，且跨日节奏可以审阅。
- 心理类角色做出了可感知的行动改变，文本不必每段硬反转；是否自然、能否在下一章维持认知和后果仍需独立盲评。

本次只解决模型输出到真实正文的可用性瓶颈；文学学习仍应以**WF 自己写→保存真实作品→具体文学复核→修改写作行为→同题公平 A/B 复测**为主线。不能用测试数取代作品质量，也不得让模型审稿建议直接修改正文或正典。
