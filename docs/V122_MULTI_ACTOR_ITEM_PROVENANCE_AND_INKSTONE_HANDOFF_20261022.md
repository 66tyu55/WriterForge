# WriterForge V122：多人物／多物件来源核验与书生额度测试边界

日期：2026-10-22；独立开发分支：v122-multi-actor-prop-provenance。
生产 main、Railway 不部署／不更新。该分支延续 V121。

## 用户要解决的问题

模型自述的规划、写作解释，与真实写出的动作不一定一致；多次修改后人物、物品和因果关系更容易混乱。用户强调“路灯”不是死板流程：关键状态有证据地提示，安静场景可以零提示，故事允许自主转向，但不能凭空出现物件转移。

## V122 真实修改

- writerforge/v122_item_provenance.py：源文本的有限中文识别器。读取已有 Novel Studio reducer 的所有 item/holder 候选状态（而非只读第一枚火髓果），在同一正文段内按原文先后顺序检查多角色交接、齿间→掌心、吞服和物件位置声明。只对有明确主语、来源位置吻合、独一原文跨度／SHA 的动作提出候选变更。多人名／物件名按最长匹配。未知“他、她、那枚果子”及多个果子同场的通用“果子”不可直接升级成事件。异常分 hard_findings／review_findings；仓库无新增模型调用、数据库或存储。
- writerforge/v116_state_delta.py：不再依赖写死的“唐蜃”或只检查第一枚果子。V122 逐项追踪物件跳跃；人物右臂的 V121 单主体检查独立保留。保留原来的法力恢复来源红线，但其文本指代处理仍有限，应单独复核。
- writerforge/v114_external_story_state.py：将 V122 中**已经证实原文出处、且未与 V114/V116 重复**的交接事件，转换为 MIT Novel Studio 已有原子归约器的 typed expected-old-value ops。归约器仍有最终否决权，出错整批不能悄悄更新。保留 V122 候选来源审计签名，已计入原有状态检查点。
- writerforge/v117_continuity_trace.py：长篇道具链可从同一次真实归约器已接受的 V116、V122 来源事件建立。写到下章不会因为 V116 忽略“从手中递给第三人”就自动退回第一位持有者。
- tests/test_v122_item_provenance.py：多角色两次交接、错误来源掌心、多个相近灵果、通用代称、被消耗后凭空再现、对话／假设排除、文本修订红线、真实 MIT 归约器跨章持续状态。
- experiments/v122_readonly_multi_item_cold_audit.py：读 R2 中原封存 V113／V114B 小说，以旧稿真实候选状态为基础，零模型模拟三人交接，再使用原版 MIT Novel Studio reducer 和下一章检验。
- .github/workflows/v122-item-provenance.yml：无文学模型 Key 的全仓库回归，加只读封存原稿工作流。

### 不可夸大的点

1. V122 是**有限源文本规则+现有第三方时态归约器**；覆盖清楚的“某人把某物从某处递给某人”等结构。不具有通用中文指代消歧、任意省略主语／隐喻／复杂多段倒叙理解能力。模糊场景需待审。
2. 所有转移仍是未经作者确认的候选事件，不是正典／模型权重训练；不自动修复或改写原稿。V113 剑穗旧未决债务保持未证实。
3. V122 不能证明一篇 1000 字玄幻追逐打斗写得有张力，也不能替代独立文学盲评。软件状态测试与文学技能成熟度是两个指标。
4. 源事件锚点长度、时间顺序、主体名称、旧状态前提是必要条件；失败或歧义不偷偷推进候选状态。

## 书生·端砚额度后续使用

平台：Intern InkStone／书生·端砚，OpenAI ChatCompletions 兼容 Base URL https://discovery-api.intern-ai.org.cn/v1。
官方模型与计费： https://discovery.intern-ai.org.cn/token-plan/home?dockey=04-model-limits-and-pricing.md&tabIndex=3
API 页面：https://discovery.intern-ai.org.cn/token-plan/home

按最新官方说明，intern-s2 等模型限时 0 墨点；deepseek-v4-flash-0731 等第三方模型需按不同输入／输出单价扣墨点。墨点不等于同数量 Token。用户今天称申请获批并有赠送额度；当前对话**不能直接验证其账号具体余额、过期时间、当前模型限额**。GitHub 历史曾配置书生兼容连接，但新获批额度和之前凭证是否同账户尚需独立确认，不应在公开仓库写密钥。

本轮 V122 的测试完全零模型调用。**下一次实际文学对照**建议预先锁定同一个模型、同一个命题（约1000字玄幻追逐打斗）、一致的温度／长度／提示协议，比较裸模型与启用 WF 状态／路灯的独立候选，保存原始输出、长度与 token usage，有限额度调用，独立文学盲评和失败案例均保留。不可因为获赠额度而自动启动无边界批量试验。
