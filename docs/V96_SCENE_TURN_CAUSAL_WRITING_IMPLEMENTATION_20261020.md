# WriterForge V96｜逐场景写作因果边界：真实源码接入、长文本结构压力测试与下一轮盲评门槛

日期：2026-10-20；独立开发分支 `v96-scene-turn-causal-draft`。上游研究与实验预注册见 [V96 GitHub开源实证研究](V96_LONGFORM_CAUSAL_WRITING_GITHUB_RESEARCH_20261020.md)。**这轮只修正式写作候选代码，未请求模型、未向R2写入、未新增训练章节，更不能宣传AI千字逻辑问题已经解决。**

## 一、真实找到的生成链断点

原代码 `writerforge/writing_assist.py::AutonomousWriting.run` 先由模型提供仅包含`objective / conflict / decision / outcome / pov`的章节计划，再用**一次模型请求输出整章**；上下章主要共享前章末尾750字符。即使结构计划漂亮，也没有把每段实际生成正文中的“人为什么行动、采取了什么行动、导致什么后果”绑定回计划与下一段写作状态。既有Xuehai、FactJournal、CraftEngine、StoryWorkTree也不会自动替模型证明因果。

V96优先解决**实际正文的结构可审计性**而非继续升级R2或学习章数。借鉴Re3/DOC的规划分段、StoryWriter事件化、StoryDaemon短视野与自由内容，但不直接复制其代码或固定机械八段模板。

## 二、实际新增的代码（已经GitHub提交）

### 1. `writerforge/v96_causal_turns.py`：只对可机械验证的局部事实作硬约束

- 提供严格有界的2–12步**临时候选**事件提纲：事件ID顺序、活动角色、事件目的、要不要接前一已完成行动的因果引用、最多2项当下写作手法触发；允许对话/安静铺垫/余波，**不强迫每一段有转折**。
- 每段模型返回`{"prose":"原创正文","trace":{"action_quote":..,"effect_quote":..,"parent_effect_quote":..}}`。B/C使用同样JSON数据类型：B=仅切段（不检查因果）；C=宿主用真正写出的正文检查引用**原句是否存在且唯一、行动在后果之前、两锚点不重叠、明确声明的前因是否在已经写出的上一场景后果中出现**。对于`没有/未/不`等明显否定前缀，程序保守拒绝或要求复核，**不自称可理解所有语义否定**。
- 可接受**外部明确作者确认**的不允许透露的知识短语列表；C在模型正文包含所列短语时拒绝，但不会自动根据词汇猜测什么知识是可信人物事实。B保留不审核差异，以便真实A/B/C对照隔离「分段本身」的贡献。
- 每段一次模型调用、没有自动纠错或失控循环；下一段只得到**前一段真实生成的有界文字尾部、最多3个在正文中定位的候选后果和当前临时写作目标**。只将这种方法称为*实际正文条件下滚动上下文*；**未实现依据真实正文重新写未来完整大纲，不能虚报全面滚动剧情规划已完成**。
- 事件定位收据只有回执SHA、turn ID、位置与引句SHA，不把原著正文、角色姓名/秘密或未获批准的模型解释变成新R2事实；所有收据永久标记`literary_causality_independently_verified=false`、`eligible_for_factjournal_KNOWN=false`、`eligible_for_experience_promotion=false`。**单句恰好存在不能证明事件间真实因果**。

### 2. 现有 `AutonomousWriting.run` 的最小改造，不再另造Writer类

- 默认`draft_mode="single"`不变，保持原来的一次性生成和候选保存接口；新增**显式opt-in** `split_only` 与 `causal_guard`。
- 原整章plan仍只是一份未验证提议；新B/C先生成有限的事件小计划（亦可接受外部**冻结、完全同样的实验计划**，使B/C同段数、同一输入提纲，降低对照混杂）；正文每次只完成一个event对应的自然片段。
- 每份完整章仍通过已有`VerifiedWritingFlow`生成packet与`save_candidate`保存，`accepted=False`，作者确认不变；B/C另在相同本地候选目录附上真实每段prompt SHA、plan和仅哈希/位置的证据清单，拒绝另外建事实知识库或动R2。
- 新增故障红色收据`chapter-NNN-rejected.json`：记录错误码、模型响应SHA、先前已写的候选段数、`automatic_repair_attempts=0`；**坏章节不进入正常 `candidates_saved`结果**，也不自行拿失败候选升级训练经验。
- 限制B/C单次最多**2章、总计最多16个写作事件**，写作中不自动增加超预算调用。单章逐场景测试输出片段保持80–950字；无模型使用实际R2/FactJournal更改。
- 兼容性：legacy A`single`返回的外层manifest不加新实验元数据、旧模型请求次数保持不变。

### 3. 本地 Studio 可明确选择，默认无变化

现有 `writerforge/studio_server.py` 的 `/api/autodraft`新增`draft_mode`可选参数并验证，只允许上述三值，B/C在排队前阻止第三章调用；现有本地 `writerforge/ui/studio.html` 增加A/B/C明确选择框和额外模型调用警告。用户不选仍是旧A路径；试验结果**不自动采用为正式正文**。

## 四、当前不能宣称解决的事实

1. C只保证人物行动和后果的**引句结构吻合**，无法可靠识别所有「如果／想象／梦境／叙述者不可靠／潜台词／复杂跨章因果」；有些真实但字面含否定的艺术场景可能被保守拒绝，需要外部文学判断。模型自填`trace`可“自圆其说”，独立审稿者仍必要。
2. 还没有真正把完整`FactJournal`人物知识、世界规则、受信现场证据实时接进C；作者显式排除的短语也只能精确字面过滤，不等于识别换说法的知识越界。长篇逻辑提升不能仅用JSON或单句证据证明。
3. 当前滚动的是**实际正文尾部与真实位置后果的局部上下文**，不是下一段动态重编多条远景情节，也没有在每个event中执行独立文学因果判决；这项优化属于后续真正写作内核实验。
4. **真实模型尚未调用，未开展800/1600/3200/6400字三臂文学A/B/C对照**，没有人工盲评、真实错误发生位置或可靠情节质量变化曲线；不允许从合成段落测试推出「AI在1000字已经不会崩」。
5. 原V92 15章云端经验、V93/94测试事件、V95CloudflareHEAD(线上404)、V49`THIRD_STRIKE_FAILED`和文学第二窗口`LOCKED`均保持，不借新写作试验违规开放正式事实写入或自动训练16章。

## 五、下一阶段优先路线（不要回到Skill和存储的无尽堆砌）

1. 先用固定原创历史/仙侠题目，把A现有一次生成、B等调用次数纯分段、C等调用次数并进行实体和因果约束的**模型真实输出**预注册，同一模型版本与实际字数；避免推测复杂场景可零成本修复。
2. 将**写出的实际场景事件**以候选方式对照已证据来源的Canon/时间/人物知识边界。允许不可靠叙述、倒叙与留白，把有疑点而非确定违规的文本排入`UNRESOLVED`，不要强制“每段因此/但是”写成模板。
3. 真实质量比较：每千字因果硬错误、首次犯错字数、人物知识越界、伏笔债务、角色主动选择、叙述节奏自然度、非套路手法适配度、独立盲评人类阅读体验。模型自己评价自己只作为诊断，**不能当晋级裁判**。
4. 如果同一问题最多两轮修复没有改善，停止本地无限补丁，查GitHub/DOC/StoryWriter/Re3/StoryDaemon源码与可复现实证，再修改底层。不给失败编辑以“修好”为名覆盖原始红案。

**成功判据依旧是小说因果更顺、人物更可信、文字更自然，而不是数据库越来越大、Skill越来越多或字数越来越长。**
