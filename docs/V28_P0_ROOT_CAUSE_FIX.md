# WriterForge V28：核心失败的底层根因及 P0 修复

**工程完成于 2026-10-16。** 这份记录针对用户提出的“WF 是不是反而捣乱；是底层还是模型问题”，关联真实结果 [第一轮 R2 A/B 分析](V28_FIRST_REAL_AB_FAILURE_ANALYSIS.md)。

## 结论：底层接口错误为主，模型评分不足以单独证明 WF 整体有害

历史实测只有一组 A/B：基线五维平均86.2、WF增强84.0、差-2.2，增强稿比基线多49.4%字符。此数据未经真人校准，也存在长度和题材差异，不能宣称“WF 平均使文笔下降2分”。但原型自由文本直接传递原著角色、家族关系、资源/伤病事件到写作指令，**确实是可从代码与 R2 数据独立验证的底层缺陷**。

要根治必须改变接口允许传递的数据，而不是增加一行“不要照抄原著”的提示词。

## 已实施并通过代码回归的修复

1. [reverse_mechanism_boundary.py](../writerforge/reverse_mechanism_boundary.py) 新建严格源文隔离层。原著只能在 Planner 阶段变成有编号的来源段落；Planner 只可返回选择的叙事机制 ID 与原文段落证据 ID，不接受自定义剧情、人物、自由文本机制描述。未知字段、未知机制、虚构段落、重复证据、越界长度全部拒绝。
2. Writer 接收到的是**宿主固定、非原著驱动**的最多两项技巧操作，例如“人物目标筛选注意”“让代价通过行动可见”。不会把 Planner 的原著事件概要、角色名字、引用和段落位置送给 Writer。这个控制在代码层面实施，不依赖小模型是否听话。
3. [reverse_cloud_ab.py](../writerforge/reverse_cloud_ab.py) 在调用批评模型前检查两稿相对长度差超过15%的情况，返回 `AB_LENGTH_MISMATCH_NOT_COMPARABLE` 并停止评分。两稿仍有生成随机性；这一关只能排除一项明显混杂，不能证明模型因果增益。
4. 新增 [test_v28_mechanism_boundary.py](../tests/test_v28_mechanism_boundary.py)，涵盖模拟恶意原著剧情字段进入 Planner、未知证据 ID、作家提示词不得含原著和证据、等长闸门必须先于评分。保留原有 A/B 安全回归。

## 重要版本隔离

已经将未来的 V28 手工 A/B 实验改为独立的 `source-isolated-ab-v2` R2 命名空间和实验版本指纹；原来的 `real-discovery-ab-v1` 成绩和缺陷保持原样，不被覆盖、不被重标为成功。付费/额度工作流 `.github/workflows/v28-discovery-real-ab.yml` **仍为仅 `workflow_dispatch` 手动触发**。本次 P0 修复与实源预检没有进行新的模型 A/B，不知道新版实际文学分数。

## 尚未完成的真正“学习能力”

**当前4种技巧是宿主固定的安全机制，并非 WF 从原著自动学出了4种新技巧。** 这是保护写作输入的第一道闸门，不能把白名单机制冒充完成用户要的文学逆向训练。后续需要独立的候选机制流程：原文事件→人物认知与叙事选择的可核证据→与宿主已有机制的冲突/反例审核→在全新原创故事中闭卷迁移→多样本独立审评→确认可复用后才授予新的机制 ID。未验证的候选只能存在于待审学习区，绝不直接拼成写作提示词。

其他未完成项包括：将真实模型 A/B 错误写入有界 `faults/forgetting` 状态、生成/批评后删除草稿前的充分审验、不同模型/真人盲评、一次失败后在新人物故事中的迁移检验、两段因果合并，以及原著场景边界的文学判断。目前训练第一窗口依然 `NOT_PASSED`，第二窗口 `LOCKED`，90%门槛没有被满足。

## 下一项工作优先级

先为每一次不合格实验持久化**仅有哈希、失败类型、长度比率、源证据和限量抽象评价**的失败凭证，而不是把失败全写进公共 CI log；再做跨题等长 A/B 多样本与独立评价。此前错误是从原著剧情产生“增强剧情”，以后成功标准必须是：在与原著无关的人物、情节和环境中，写出自然的感知、判断、行为和后果，并实证优于相同模型的无技能基线。
