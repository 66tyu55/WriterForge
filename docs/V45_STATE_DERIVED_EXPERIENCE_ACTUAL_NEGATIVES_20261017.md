# WriterForge V45｜经验执行机制修复、旧证据不可篡改、新反例验证

日期：2026-10-17。V45基于V44独立分支，保留V38、V43、V44的全部原始SHA、失败和论文角色冲突记录。V44 PR #49、真实负对照审计 SHA f83cb2199055b1a645028f6139605556ffbb31241ae911379d2f244cdbe353cb 原封不动。

## 真正修改的生产执行链

- 新增 writerforge/v45_state_experience.py。读取现有WriterForge数据库character_state和causal_events里持久的事实与事件，自动选择是否使用V38 L2候选策略。作者/考官不能临时直接输入一个替WF写好的自由文本因果计划。
- 进入正式 writerforge/verified_flow.py 的VerifiedWritingFlow.prepare接口后，先将当前故事状态推导的人物已知/未知、线索、计划行动、后果及备选解释按SHA锁定，随后把实际有界策略送入真实生成prompt；默认未启用的V43和原路径不变。
- 当同一fact ID同时被标记已知/未知、事实已提前揭示、线索角色仍有争议或已经明确回收时，按条件暂缓该策略，而不是硬性要求所有题材使用伏笔。
- save_candidate新增实际正文的观察/行动/后果/揭示四引用，并要求前后引文包含同一线索短语、行动确有同一人物。仍不具备自然语言因果语义判定能力。
- 评审回退改为HMAC-SHA256完整回执认证：没有共享审稿密钥或签名不符，不能只靠一个声称独立的布尔值触发策略暂停。MAC只能证明持钥者及字节完整，**不证明审稿意见独立或正确**。两份不同场景的经认证负反馈可以暂停，永不自行文学晋级。

六个新情境：海岸邮差、雪镇旅店、果园合伙人、沙漠巡护、运河船工、剧团服装。每组从同一个真实原著章节结构与WF发布的学海出发，比较默认prepare与V45启用prepare。6/6实际生成请求变得不同；早期V44的6/6写作prompt相同问题得到工程解决。

## 新证据证明仍存在根本缺陷

更难的反例同时包含同一个人物“青禾”和线索“铜铃”，四条引文真实存在且按顺序排列，但中间的买盐行动与山坡暴雨彼此无因果。**V45依然可以接收这组结构证据。** 它明确返回causal_semantics_verified=false，因此此结果绝不表示文学伏笔成功；这条负例必须保留并在下一版继续对抗。

实验中的结构化人物知识由测试程序种入WriterForge数据库，不等于WF从原著文学语义自主学习，也没有真实创作六篇自然小说，更没有独立读者盲评。

## 是否真的有用？

生产执行策略有工程价值：WF自己的持久故事状态已经能有条件地改变真正的创作请求；可拒绝几类具体错误、回读不可变计划，并可认证暂停。

**文学能力仍未通过。** 限于事实ID的检查无法识别同义的已知/未知矛盾，无法证明行动后果与伏笔有文学因果。真实自主经验形成与作品质量改善均未验证；第一课程NOT_PASSED、第二LOCKED，V45保留Draft，绝不自动合并正式Skill。

建议下一步专注一次有价值的新作品盲测，而不是增加模块或为了测试通过制造越来越多模板。
