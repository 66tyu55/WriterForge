## IV. 本轮底层修复及未解决的理论问题

- `writerforge/reverse_discovery_models.py` 新增**仅 GLM Writer 可选**的 `reasoning_effort=low`；经端砚真实无原著短篇探针验证 gateway 兼容，不改 V7 和其他厂商模型的默认参数。GLM 不能简单冒充已关思考。
- `writerforge/reverse_cloud_ab.py` 新增可选三角色输出预算 `role_tokens`；有界预算形如 Planner 5500、Writer 8500、Critic 7000，为多次实际模型传输/输出尝试留空间，并保留每轮50k/7调用硬上限。
- 同模块新增可选 `common_target_chars`：A/B 两组共用同一目标字符数，不能在评审前靠事后裁剪/补字强配。V9真实结果表明模型仍不够听话，属于不充分修复。
- **最新非破坏性底层修复**：新增可选 `symmetric_length_revision`，若两组首稿不等长，则**两组各接受恰好一次**相同的独立稿修订机会。Writer 只见自己那稿和相同中立长度目标，不见另一组、原著剧情和私有密钥；复写后仍检查15%闸门；任何一步失败立刻停止、保留静态失败原因、不生成模型文学分。角色组合预留必须满足 Planner + 4*Writer + Critic <=50000；这条新机制只是逻辑与合成测试，**没有产生成功的真实GLM长篇复评证据**。
- 先前文学核心仍有根本局限：Planner 的证据ID语法合法不等于语义正确；四种宿主技巧不是 WriterForge 自动从原著学习的技巧。`evidence_first` 弃权与负例上下文隔离仍须显式启用；多章重测的正负分差是“模型审评观察”，不代表独立真人评价、遗忘测试或真正学到新的文学机制。
- 所有这批新代码为**可选扩展，默认不改变旧 CloudABTrial 调用、已验证 R2 snapshot、旧来源解析器、固定模型身份与创作任务**。新增纯合成测试检验同时修订两稿、源隔离、预算硬限制、无遗失已有功能。最终 CI 必须以最新 commit 测试结论为准。
