# V33 修复冻结协议：WF 输出字数硬约束 + 评阅 JSON 问题一次解决（2026-10-17）

用户明确授权“可以---修补--必须控制WF指定的输出长度--然后json格式问题--一直没有处理--这次一起解决”。此轮先修后验，不以零内容补齐、硬截断或选择高分来冒充文学提升。

## 历史实际失败与本次根因修补

V32考官三题的真实证据：陶镇无记忆稿897字符 vs有实验记忆1172，虽然各自在850–1400建议范围内，**相对篇幅差23.5%**导致不能比较；马场、运河各写了两份稿，但评阅返回结构不符合约定JSON，两个题无有效文学分。这是写作长度稳定性与评阅接口可靠性两类不同问题。此前 V28/V29已发现写作稿同时偏离指定字数目标，不能把相对公平当作绝对长度达标。

新协议 `writerforge/v33_exam_contracts.py` 与 `writerforge/v33_balanced_writing.py`：
- 对任一写作考题，不只是“尽量”而是由程序**精确计算**，以含标点字符数**目标1120、绝对合格区间950–1300、双稿相差≤15%**共同约束。每道两份由同一个GLM5.3模型写，控制组和唯一冻结记忆组得到同一要求。
- 初稿任一越界或两稿比例不公平，**两组各一次公平对称修订**，每人只看自己的初稿、自己真实字符数、与1120目标的增减字符数、共同的950–1300区间，不见对方稿长/文本，保留人物因果、完整转折与结尾。修订后重新测量，**仍越界就拒评、不得硬剪或空格填充**。
- 相同的小说全文直接标记 `IDENTICAL_DRAFTS_NO_MEASURABLE_EFFECT`，不能让两个评审打出凭空的进步。
- 考官 JSON 采用**固定字段集合**：顶层A/B/uncertainty，A/B的perception、causality、information、continuity、language各有score（整数0–100）、reason（4–180字符），uncertainty限制4–180。不再以示例分数“75”锚定模型评分。只允许单层或双层的**唯一无歧义包装**`result/review/grades/ratings/evaluation/data`，不接受缺字段、多余字段、整数外类型、超长评论，绝不补造分数。
- 首次返回结构错误，才允许同一评阅模型对**同一道题、同两篇匿名原稿、相同A/B位置**做一次有限格式修复调用，且记录首次错误代码、额外调用；首评合法则**不得再次评分挑高分**，第二次还不合格直接失败并保留错误证据。
- 冻结硬预算每题`DiscoveryCallBudget(max_calls=8,max_reserved_output_tokens=50000)`，初稿写作每臂7500（总15000），对称修订每臂6000（总12000），两名评阅者每人最多2调用且每次5300（总21200），总预约最多48200；网关自身的截断/连接重试也要额外计数，不得超过硬上限。
- 以前的已持久V31第二轮唯一实验记忆继续只读（两版 SHA见V32），不允许从考卷偷学或在考试时修改规则。旧V32 0有效分状态永久不改。
