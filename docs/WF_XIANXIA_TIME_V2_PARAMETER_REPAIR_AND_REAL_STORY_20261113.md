# WF 修仙时间：先失败、再矫正参数、再测新角色（2026-11-13）

状态：**SHADOW，时间计算通过，真实故事仍未通过**。此报告只记录已发生的测试与其缺陷，绝不因为模型能返回小说就宣称已经学会了玄幻世界。

## 1. 测试先于改码：两处实质性错误

1. 旧版 `time_v2.py` 没有任何可以消耗世界时间的区域转换事件。角色在三倍流速洞府修炼后，即使剧情写出离洞，角色的 `frame` 仍为 `cave`，后续年龄与修炼时间会继续错误按三倍计算。冻结 8 个新反例，[GitHub Actions RED #43394330940](https://github.com/66tyu55/WriterForge/actions/runs/43394330940) 出现 **6 errors + 2 failures**。随后加入 `cross_frame`，分别计算原区域和目标区域的世界时间、人物主观经历时间，严格消耗时间成本，其他 NPC 并行前进，跨界本身不算实修。同一批转绿。
2. 原有 `time_bridge.concise_context` 错误内置“河水预计”“洞外守夜人”等旧故事名词，切换随机故事会污染新文本。冻结反例，[Actions RED #43395320106](https://github.com/66tyu55/WriterForge/actions/runs/43395320106) 失败。现在事件名与其他人物名称由当前故事提供；时间 Skill 本身只提供当前时间、地点时间流速、实修累计、最少所需世界小时、截止前资格可达性。
3. **新模型调用完成后才发现的第三处错误**：第一次自主行动成功登记在世界时刻 2009，但第二次生成小说还拿着事前的 2008 时刻。冻结回归，[Actions RED #43397301939](https://github.com/66tyu55/WriterForge/actions/runs/43397301939) 失败。修正后，合法且成功提交的行动必须先推进世界状态，后续作者上下文读取**行动后的世界时钟**；被拒绝的行动不能推进时钟。此改动仅作单元测试，没有回头重跑已冻结的模型答案。

## 2. 重新设计后的参数约束

所有数字均具名、带单位，并分开作用：`world_clock.hour`（全世界唯一时钟）、`actors.*.frame`（当前局部时间参考系）、`time_frames.*`（精确主观时长/世界时长比例）、`age_subjective_hours`（在该设定下的年龄经历时长）、`lived_subjective_hours`（累计主观经历）、`cultivation_subjective_hours`（实际修炼时长）、`min_cultivation_subjective_hours`（当地最低时间资格）、`latest_world_hour`（特定事件截止时刻）、`era_history`（未知纪元差距不能擅自写数字）。

`cross_frame` 必须声明离开旧区域耗时、进入目标区域耗时；对同一个世界事件，角色与 NPC 的时间全部推进。突破仍由作者选择并可失败；失败没有理由被自动解释成世界观错误。

冻结新随机人物：种子 **20261114**，“**山门守钟人，多疑但重诺**”；视角外普通老人独立活动。两组世界初始 2000，洞内6小时修炼、跨界2小时，到世界2008；冰桥2012关闭。仅把洞府倍率由 1:1 改成 3:1。前者累计实修14、后者26，突破最低资格22，洞外老人均度过8小时。即使×3可以成功尝试，作者仍可选择敲普通警钟而非升级。

**最终确定性测试**：[GitHub Actions #43397382727](https://github.com/66tyu55/WriterForge/actions/runs/43397382727)：原始V1历史回归 **11/11**、V2修正及作者界面 **45/45**，合计 **56/56**。这证明参数可计算并能约束所提交的动作，不是文学质量或作者自觉性的证据。

- 两组**做出相同的合法选择**并非错误：谨慎的人即使具备突破资格，仍然可以选择普通救援。但这组测试不能证明改变洞府倍率就让作者产生不同情节。
- ×1 的严重重复是**模型语言生成故障**，不能归咎于时间计算错误，也不能因为时间登记通过就算写作成功。
- ×3 故事中实际写出额外出入洞府等行为，然而只提交过一次手敲钟的动作，账本没有后续事件；我们不能凭空假定这些动作一定花了足够时间。对应小说必须标为**正文时间未验证**。
- 上述两个模型试验是在第三处“滞后时间上下文”修复之前完成；第三处修改对未来的新故事生效，**本次不重复调用模型**，没有证据证明修正后能提升小说质量。

## 4. 不应该继续做的事与下一步

现在更清楚的边界是：**底层时间参数的设计已经足以执行跨区域、并行人物计时和一个境界资格判断；写作链路的跨回合世界状态还未形成可靠闭环。**

继续增加小数权重、假设玩家必然突破、直接把作者正文替换成系统预制结局，都无法解决重复文字或未登记动作。

未来若继续，需要让**作者提出一个行动 → 时间内核仅判可行性和代价 → 写作消费提交后的状态 → 作者把下一行动正式登记 → 继续真实故事与后果**。每次成功提交必须留一次世界状态与原始正文的对应记录，失败不能装作通过。必须与已有 WF 人物认知边界分别验证。不要用时间 Skill 代替文学模型或所有世界规则。

**当前决议**：本次修正并保留 SHADOW 时间 Skill；不把它当作独立写作能力，不合并生产、不改唯一学海、R2、Canon、Railway、main。保留红灯和原始失败输出，不进行结果条件下的模型补测。
