# WriterForge V123 — 20 章复仇目标回归与长期人物承诺

日期：2026-10-22。开发分支：v123-twenty-chapter-revenge-continuity，起始基线 V122。生产 main 没有修改；Railway 没有部署。

## 结论（分层，不能混淆）

1. 截至 V122，WF 主要保证部分物件、伤势和有来源证据的时态变化，V117 会长期保存未解的状态冲突，但无法证明一条作者确立的复仇线过了 20 章仍在写作流程中得到正确约束。
2. V123 增加**需作者明确确认并有原始正文引句的一个复仇目标**，放进既有 V117 resume，而不是新建数据库或增加模型调用。中途 19 章无关时不填充复仇提示；第 20 章人物／仇人重新相关时，规划及正文提示重新提醒目标、动机与认识边界。
3. V123 对“报了仇”“大仇得报”等明确正文结案声称给出 source-only 复核提示，且**绝不自动将旧目标设置为完成**。但因存在真凶反转、误解、放下仇恨与间接解决等合理写法，这些中文句式尚不能安全地作为通用硬拦截条件，正文会保持待审、不是全部自动拒绝。
4. 本轮验证的是**20 次真实归约器执行／已有 V117 跨章快照序列化恢复**，输入章节文字为合成测试材料，并非花费 Token 真正生成的 20 章小说。通过此测试不等于证明 WF 写作质量、完整因果理解或长期文风已成熟。

## 具体实现

- writerforge/v123_long_arc.py：
  - register_revenge：只接受明确 author_confirmed=True 且原文能找到唯一引句的开局，原文／引句记录 SHA，剧情由外部作者确认。支持 AUTHOR_ASSERTED 与 CHARACTER_BELIEF，不能把人物误认自动变为事实。
  - advance_open_revenge：只允许逐章推进，严格校验项目、场景、前一章节、哈希与固定长度限制，不得跳号、重放、串小说。记忆大小随章节数保持基本不变。
  - relevant_revenge_hint：目标或复仇事项与当前段实际相关时才提示；不把每个安静场景强行变成复仇桥段。提醒人物可查证、放弃、和解或改写行动，但结束需要有真实情节和授权审查。
  - audit_revenge_prose：只核查新正文中可定位的显式声称；对话、假设、梦境不当作事件；模型自述不能自行把 OPEN 变 COMPLETED。歧义标待审，不制造刚性剧情结论。
  - read_long_arc_from_resume：先验证 V117 外层续写快照，再验证内部作者确立目标的哈希、项目、场景与章节对应。

- writerforge/v117_continuity_trace.py：make_resume(..., long_arc_checkpoint=...) 为完全可选输入；没有长期目标时维持原有格式／读写行为；带目标时嵌入原有有哈希的未接受续写凭证并在 read_resume 时校验。

- writerforge/writing_assist.py：
  - AutonomousWriting.run(..., long_arc_checkpoint=None) 仅 continuity_guard 可用。
  - 如果旧 resume 自带 V123 目标，读取时自动恢复；不允许调用者悄悄覆盖、变更项目或跳章节。
  - 如果作者额外提供长线目标，则必须有已保存、匹配上一章节的 resume，防止凭模型规划临时创造所谓作者正典。
  - 当本章用户目标涉及仇人／复仇时，在生成本章计划之前即可加入目标相关来源提醒；具体的回合也要按 relevance 单独提醒，并由 V121 预算机制保护这类来源约束。
  - 每回合的实际文本按 V123 source-only 审核，审查记录入原有 V96 evidence；完整章节结束后只按真实正文推进目标章节计数，序列化进入原有 V117 resume，不额外触发模型。
  - legacy single、原物件追踪和 Novel Studio 时态归约器都不被隐式更改。

## 重要局限与下一轮目标

- 本次只做了**一条经过作者注册的复仇线**。不能宣称所有未注册的人物长期目标会被 WF 自动发现，也不能把测试里明确的引句识别等同于通用中文叙事理解。
- 通过的是 20 个合成段落／快照的机制可靠性，不是 20 章真人文学盲评；模型依然可能无视提醒，产生有心理动机问题、缺乏张力或复杂语义矛盾的正文。
- 非明确的跨句指代、误认真凶、线索变化、不同目标的冲突及已解决目标的独立证据尚待扩展。当前结案声称只能进入待审，不作全自动硬拦截；这比拒绝合理转折或伪造真相安全。
- 如果不传递 V117 resume、在非 continuity_guard 模式启动、或者该长期目标未经作者登记，WF 当前不能声称自己会在第 20 章记得它。测试没有改变 Railway 正在运行的旧版本。
- 已有 story_commit.SET_PROMISE 可处理作者正典中的承诺，但并未在本轮证明它与 V123 的候选目标双向同步。**不要声称书写或读取正典 promises 已形成自动闭环**。
- 下一次真正验证文学能力，应限定同一模型、同一章段的近千字原创，在书生赠送额度的实际计费核验后进行盲测；把模型能否在含蓄转折中正确保持复仇动机与人物弧线，和精确物件状态检测分开评分。

工程原则：真实原文才可更新候选事件；作者确认才可确立或变更人物长期目标；模型的自述、下一章大纲、引用片段本身均不能成为结案凭证。
