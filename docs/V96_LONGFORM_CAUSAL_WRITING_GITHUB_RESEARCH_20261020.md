# V96｜长篇小说「约千字后逻辑漂移」：GitHub实证调研与WriterForge写作内核实验方案

日期：2026-10-20。**这是写作能力优先的方向纠偏**，不是再做一轮R2存储升级、不自动调用模型或修改生产WRITE。接续 [ADR-001长期记忆](ADR_001_WF_LIFELONG_MEMORY_DURABILITY_20261020.md)，但评判重心从「存了多少经验」转向「写长之后是否真的知道谁、因何、怎样做出了哪些改变，文字是否更自然」。

## 0. 本轮问题与结论的证据界限

用户指出：不少AI写作看似前几百字顺畅，但写到约1,000字时动机、因果、视角、伏笔开始混乱。**暂作为WF待测假设，不是已被学界确立的所有AI统一断点**。需把输入上下文长度、输出字数、一次性生成还是连续接龙、中文字符/英文词数、情节题材及模型版本单独记录，才能解释。

**找到的是有实测提升的局部方法，还没有一个开源项目以可靠、可复现、跨题材长期人审证据证明「彻底解决任意小说的长篇因果/文学性」**。在基础逻辑未验证前禁止宣称训练章数、上下文1M/150k token、漂亮示例或自动评分等于写作能力进步。

## 1. GitHub谁真正针对长篇写作逻辑做过解决尝试

### 核心交叉发现

- **DOC/Re3有真正发表的真人评审相对优势**，因而最值得优先研究其细化计划、续写候选筛选、实际生成段落与计划的强匹配。
- **StoryWriter专注事件间的逻辑关系**，适合把WF长篇因果描述转成可查询的「前提→行为→后果」关系，但不要指望直接导入其研究脚本成为稳定服务。
- **StoryDaemon尤其适合不被模板僵化的原创性**：用少量必要规则守底线，事件可以自由生长；下一场景的计划应由实际正文重新计算，而非一律盲从一开始的大纲。
- **ConStory-Bench告诉我们应测何时开始出错**：目前更强的公开结论是故事事实和时间维度出错、容易集中在叙事中段。没有证据说任何模型一旦输出中文1,000字符就必然失控。WF必须自行量测位置曲线。

## 2. WF现有写作链的直接漏洞（已按GitHub真实源代码核查）

主要参照：
- [writerforge/writing_assist.py](../writerforge/writing_assist.py) 中 `AutonomousWriting.run`：`MAX_CHAPTERS=6`，先用模型得到`objective/conflict/decision/outcome/pov`五个文字字段；之后**一次 `local_chat_completion(...,max_tokens=2600)` 输出一整章候选正文**，没有场景事件的逐步执行与正文每步状态对账；下一章只携带 `previous=body[-750:]` 的尾句，plan里没有「真正发生了什么、是否因为行动造成、谁能知道」的来源化验证。
- [writerforge/verified_flow.py](../writerforge/verified_flow.py)：写前有Xuehai源码检索/技法候选/独立授权，正文连续性只读**最近2个已接受场景各尾部至多1400字符**；这不是世界观全局状态和因果承诺自动重放。V92存了15章经验不等于真正逐段约束创作因果。
- [writerforge/story_work_tree.py](../writerforge/story_work_tree.py)：`CAUSALITY/CHARACTER/SCENE/CRAFT`等工作树和调度存在，但它是调度抽象，不会自动证明新写正文遵守了「必须有前因后果」。
- [writerforge/craft_engine.py](../writerforge/craft_engine.py) 与 [scene_craft_teaching.py](../writerforge/scene_craft_teaching.py)：有条件化技法建议和场景应用，部分可改善文风，但**技法选中**不等于对应的事件/情感/关系在正文中真正生效。
- V85/V89、FactJournal、V86、V92–V95已有真实来源/角色知识/候选审核/经验云端恢复的子能力，但**核心写作入口尚没有：真实段落生成 → 自动提取实际事件变更 → 主线/人物因果预案校对 → 差异修订 → 状态提交后才能继续下个段落**的完整执行闸门。

**因此优先处理的是 WRITER 真实写作思考与正文驱动闭环，不是增加下一套R2存储服务、另一批Skill、更多上下文或新付费训练章数。**

## 3. V96拟议的最小写作思考闭环（阶段性实验，不能冒充已上线）

```text
作者给出本场景目的/人物 → 模型提出3-5条有因果的候选事件
       ↓ 预备：角色欲望、可知信息、阻力、可行动作、代价与伏笔债务
选择一条短距离滚动剧情方向（非永久僵硬大纲）
       ↓
模型自由写一个戏剧事件对应的正文片段（计划输出200-500汉字可测区间）
       ↓
事实与叙事对账：角色身份、知识时间、物品、行动前提、具体后果
       ↓
阅读因果：可观察行动是否产生了新的选择/阻力/关系状态，而非只靠修辞宣称变化
       ↓
PASS：保存真实正文与实际事件增量，更新下一次可见状态及短滚动方向
REJECT/UNKNOWN：原文留候选、保存失败证据，禁止自动把虚构推断写为KNOWN
       ↓
后续段落只取与当前人物/事件/未结伏笔有关的少量上下文，长篇继续
```

关键区别：
- **先有可检验的变化，再生成解释变化的文字；更要根据实际写出的文字复核变化是否真的发生。** 不能光看JSON计划就宣称正文有逻辑。
- **分开硬约束与软创作**：硬规则仅约束同一本作品的身份、时间、人物所知、不可违反的世界规则和已证实事件；风格、节奏、误会、留白、插叙、叙述者不可靠都是允许的软空间。出现争议就标`UNRESOLVED/INTENTIONAL_AMBIGUITY`等待复核，不能把每一次插叙误判成时间线错误。
- **因果关系必须可辨别**：局部事件要有已知前提、阻力、角色决定/行动、可观察后果与可能替代解释；真正文学动机不能机械地由SHA、距离或相邻位置证明。
- **技法必须服务剧情**：每场最多激活1–2种相关技法，检查其在行动/细节/对话/人物误解中产生了什么阅读效果；不能一段接一段复制“作者讲道理”“人物悟了”“命运转折”模板。作者认可的语体优先，不能强迫现代网文变成固定西方八段式。
- **不新建长期角色库**：复用已存在的FactJournal/经验选择与R2锚点；写作者只追加候选实际场景状态，获得外部独立文学审评前绝不自动晋级`KNOWN`。

## 4. 「约1000字崩逻辑」如何严谨且有界地证伪/证实

### A/B/C三臂实验（预注册；本轮尚未调用模型）

**相同原创题目、同一模型版本、同一人物知识、相同长度目标、固定初始设定与任务顺序打乱**，不允许先看盲评答案再挑题。

- **A 原现状**：一次性输出完整章候选，如同现有 `AutonomousWriting`（保存全部中间输出与错误，不修好后冒充初次成功）。
- **B 仅拆段**：同样的事件意图/背景，按同样长度分块写，但不用动态事实/因果闸门。该臂用于隔离「仅增加API调用次数/段落切分」的作用。
- **C 逻辑状态驱动**：与B同样的调用次数、分段目标和预算，仅增加「滚动事件预案、字符位置来源校验、人物所知/因果/实际正文状态变更检查」。同一个模型自己改错不算独立评分。

第一轮小试两类**原创**情节（历史人物博弈 + 仙侠因果冲突），目标`800/1600/3200/6400`个**含标点中文字符**；观察每段第几个字符首次发生可信严重矛盾，而不是假定1000正好是阈值。若原故事太短、人物太少不能构成逻辑任务，重新定义情节复杂度，不填充废话冒充目标长度。正式对照可扩为3–4类型、不同模型供应商；不使用同一家两模型冒充交叉验证。

记录两组指标且**不可互相替代**：

| 结构安全指标 | 文学成长指标 |
|---|---|
| 因果断裂/无前提就行动的次数及首犯字符偏移 | 对话是否体现独立人物声音，避免词换了而行为不变 |
| 人物不可能知道的信息、知识泄漏与先后时序冲突 | 冲突是否自然升级且代价真实，是否有戏剧行动而不只是解释 |
| 地点/能力/物品状态跳变、已明确事实被覆盖 | 伏笔是否自然设置与回收、克制及留白是否恰当 |
| 事件前提-行动-后果是否闭合、剧情线是否被遗弃 | 语言/节奏的场景适配性，不因统一模板变得机械 |

统一报告：按每千中文字符的错误率、错误严重度、最早出现位置、跨场景一致性；保留未完成/拒绝/弃权和每个修订次数，禁止只选获胜样本展示。评审者在不知道A/B/C归属的条件下单独核验具体片段/证据；没有真实独立评审只能报工程一致性，不能宣布写作水平提升。达到两次同源修补仍不改善，停修，查外部方法/失败模式，不无限付费重试。

严谨区分**逻辑没错但故事不好看**与**故事精彩但存在硬矛盾**：前者需要写作手法诊断，后者需要事实/知识/前提修复。不得用`JSON PASS`、评审自评分、模型长度或草稿Token代替人类文学质量判断。

2. **尚未执行**：WF新场景级滚动写作控制的代码改造、每段正文事件核验、真正多字数3臂输出、收费调用或独立真人文学盲评。无新文学生长可宣称。
3. **下一步最高优先级**：**不要先重复V95/R2 HEAD infra**。先在现有 `writing_assist.AutonomousWriting` 可选择的实验开关后面引入小型`scene-turn`写作/评审迭代，复用FactJournal角色时序、StoryWorkTree现有`CAUSALITY`节点及已有写作技法，保持旧一次性写作行为可作为A对照；先用合成反例测“错误如何拒绝”，再用用户已批准的模型预算走真实独立盲测。

**单一成功判据**：在相同模型、长度和题材下，C相较B显著减少真实证据支持的因果/知识硬伤，且**独立人类盲评未显示明显文风或戏剧性退化**；没有这个结果就只叫“结构测试通过”，不能声称WF解决了AI千字逻辑混乱。
