# WriterForge 0.BL｜学海真正服务玄幻创作：原文溯源、细节场景册与效用实证计划

日期：2026-10-28。性质：**研发执行计划及首批候选材料，不是已完成训练、已证文学改善或发布许可**。只允许 refactor-unified-scene-delivery-audit；不修改 main / Railway / 正式 Canon / 用户受保护的 R2 原著；不重放 0.AY GLM 429 或旧付费文学训练。保留 V26/V98/V119、唯一 NarrativeCore、作者独立选剧情与删改的主权。

## 一、为什么现阶段不能只增加小说文本

[0.BJ](WF_0BJ_FIRST_HUMAN_REVIEW_INVALID_TRIAL_STOP_HANDOFF_20261027.md) 的第一次真实读者否决了原实验资格：有一对逐字复述上文且两臂相同，有大量不到预定长度的输出；过去多次只是在 prompt 中静态塞了 v1/v2 文本，并不代表真正运行 WF 写作闭环。

本次核对源码后还有更加直接的产品断点：

1. 原 writerforge/xuehai.py 的 XuehaiStore 已具备 LEARN staging/publish、delta 快照、FTS5、质量/新颖度/单作品去重/使用次数及有界查询。这个基础必须保留而非再造独立记忆。
2. 原 writerforge/verified_flow.py 的 VerifiedWritingFlow.prepare 确实按体裁与需求调用 XuehaiStore.query，选取 evidence 并把作品章节索引保存在 GroundedDraftPacket；但实际写作 prompt 以通用指令、确认设定和用户认可的单段文风示例为主，**并没有把 evidence 所对应的可迁移场景操作交给作者模型去选用**。现有元数据 function/effect/method_cluster 太粗，不能代表已验证的文学手法。
3. 当前检索首先严格按 genre 字段精确过滤，某些细分类型（玄幻、仙侠、修真、志怪、武侠、古代白话）会出现空命中或只按质量权重返回不相干场景。函数偏 environment/dialogue，不足以表达炼器工艺、破境身体代价、宗门利益、阵法空间状态等细节。
4. 原 tests/test_v33_learn_archived_modern_r2.py 证明**七个现代作品的历史归档校验配置**（fanrenxiuxian、doupo、wudongqiankun、wanmeishijie、zhetian、manghuangji、qiumo）存在，**并不证明当前可读取、授权商用、已学到有效方法**。因此绝不可自动恢复、重新付费解析或上传它们的原始正文。

**目标不是“库越大越会写”**：首先解决每条经验有来源、在什么场景被调用、为什么适合/不适合、调用后作者做了怎样的选择、有没有带来收益。没有实际用户/读者证据的经验只能保持未验证状态。

## 二、三层材料，绝不混淆身份和版权

**A. 传统古籍原文（优先）**：从已进入公有领域且有明确版本来源的古典中文文本开始。选定版本/回目/原文文件 SHA、确认电子校注/现代译本附加版权。原文只在 LEARN 阶段解读、引用限定短句和出处，WRITE 以可迁移的简短机制卡为主，不把整段原文送给生成者。首批作品源链接：
- 《西游记》第一回（世界设定从宏大秩序落到具体一事，世界尺度与感官边界）：https://zh.wikisource.org/zh-hans/西游記/第001回
- 《聊斋志异》各篇（奇异细节与人物反应，身份未知时的恐惧/欲望）：https://zh.wikisource.org/wiki/聊齋誌異
- 《世说新语》（短言语中社会位置与人物气质）：https://zh.wikisource.org/zh-hans/世說新語
- 《史记》卷七项羽本纪（意图、选择、权势、后果与对抗者立场）：https://zh.wikisource.org/zh-hans/史記/卷007
- 《红楼梦》程甲本第一回及可核查回目（生活细节、礼数、误判、隐含关系）：https://zh.wikisource.org/zh/紅樓夢（程甲本）/一
- 后续候选：《水浒传》《儒林外史》《镜花缘》等，先核对数字版本/权利后才入库。
这些“手法方向”是首轮研究假设而非已逐章审订的结论。中国哲学书电子化计划 CTP 的 FAQ 特别限制其网站内容再发布和自动批量下载，**不允许把网站可读当成可整站爬取的许可**：https://ctext.org/faq。选用维基文库时仍检查具体页面、底本与追加注释/译文的授权：https://zh.wikisource.org/wiki/Wikisource:版权信息/全文。

**B. 现代玄幻、仙侠作品（版权隔离）**：按题材建立公开的“研究书目与待验证技能类别”而非未经授权复制原文。既有七部历史归档配置只登记 work_id/原件指纹、可能的题材覆盖，当前不访问 R2 正文、不把文件发布到 GitHub；将来如有作者/版权方许可的片段或明确合法的用户授权样本，先做 RIGHTS_VERIFIED，再提炼受限的短方法卡。版权未确认时 status=REFERENCE_ONLY_RIGHTS_UNVERIFIED，禁止保存长段原作、发布或进入生成 prompt。避免“AI 已学习某名作”的虚假宣传。

**C. WF 自创场景（可立即开始）**：为玄幻细节单独写原创、非既有小说照搬的 60—120 字示范，并标记 AUTHOR_CREATED_DIAGNOSTIC_NOT_NOVEL_SOURCE。它们能在干净测试数据库中锻炼分类、检索和故障复现，不代表从真正名家那里学到的经验，更不冒称具备文学收益。此轮首批原创 seed 另见 experiments/wf_0bl_xuanhuan_original_micro_scenes_20261028.json。

## 三、必须覆盖的玄幻场景与“细节为什么重要”

先建 16 类场景矩阵（目标覆盖率，不是现在已经学成）：

| 场景 | 真正要储备的细节与可迁移机制 | 最容易出现的坏写法 |
|---|---|---|
| 灵根/资质检测 | 器物可靠性、检测权限、隐瞒成本、社会位置变化 | 只写光芒颜色和惊叹 |
| 练气/闭关日常 | 时间流逝、饥疲、药材库存、师承约束、异样征兆 | 升级数字代替身体与选择 |
| 炼丹 | 火候、药性相克、前序操作影响、失败代价、闻味识变 | 堆药名与七彩烟雾 |
| 炼器 | 材料应力、器纹、冷热、匠人的手感、工具限制 | 几锤后神兵出世 |
| 阵法/禁制 | 视线盲区、阵眼/供能、触发条件、误判、连锁后果 | 无限法力、规则临时改变 |
| 丹田/破境 | 旧伤、代价、理解瓶颈、旁观者有限认知 | 所有突破都靠痛喊 |
| 灵兽/驯养 | 嗅觉与行为、资源交换、野性、建立信任的时间 | 宠物突然全知忠诚 |
| 近战斗法 | 脚下地形、站位、呼吸、法术间隔、后续反噬 | 只有轰鸣和特效名 |
| 远程神通/法宝 | 距离、视野、载荷、弹道、误差、代价与反制 | “一道光”解决一切 |
| 宗门政治 | 配额、规章、人情债、名位与真实话语权 | 所有人只会嘲讽主角 |
| 市坊交易/拍卖 | 真伪检验、信誉、价格信息不对称、暴露身份的代价 | 所有买卖都靠捡漏 |
| 秘境/遗迹探索 | 现场痕迹、先后进入者、错觉、路线选择、存货 | 每扇门后都是奖励 |
| 志怪/神祇接触 | 异常细节先于解释、目击者差异、禁忌代价 | 用旁白立刻说明怪物来历 |
| 家族/师徒与恩怨 | 不说透的动机、旧承诺、沉默、权力差、真实选择 | 每段对话像交代设定 |
| 伤病/失败与代价 | 恢复过程、误治、伤势对下一幕动作的限制 | 每场战斗后无损满血 |
| 旅途/边境/凡人生活 | 食宿、身份、物资、季节、阶层差、局部观察 | 跳地图无时间成本 |

每条机制卡至少写清：适用触发、具体可观察物理/社会细节、人物可知信息、所改变的选择/后果、反例与不适用条件、来源版次与许可、是否真实来源分析/原创示范/未验证假设。**不能把“加入更多细节”当作技法**；必须解释为什么这个细节在此场景产生叙事作用。适合留白的场景允许返回 NONE，不强迫场景遵循账本。

## 四、现有 SQLite 的执行结构：别另造记忆模块

P0 将证据分开存储但继续使用现有 WriterForgeDB 和 XuehaiStore：
- LEARN：可追溯源条目保持 xuehai_entries / source_spans，采用现有 snapshots 的 STAGING→PUBLISHED 和 delta 继承；研究候选新方法卡必须与源 entry_id/版本 SHA 相连。未核实的书目只作为参考索引，不创建“已学习”条目。
- METHOD CARD（同库表，不是独立服务/记忆）：entry_id、scene_type、specific_signal、detail_observation、mechanism、writer_option、counterexample、limits、source_uri+edition+sha、rights_status、review_status、value_status、quality_evidence，不存未经许可的长段现代原文。
- WRITE：由 writer 的实际 goal、人物局限和场景类型形成结构化查询；先过滤 rights/review/source_snapshot，最多返回 2 条、合计不超过 300 中文字符的**迁移操作**；绝不直接复制原著或发出“必须按此写”的强制指令。仅将作者可能采用的几种处理方式及适用条件交给原作者模型自主选择，可不使用。回执记录 source/方法 SHA、命中/拒绝/无命中/原文字节是否泄漏；继续使用唯一 NarrativeCore。
- 检索采用精确证据 + 体裁层级回退（修真→仙侠→玄幻→广义叙事；志怪古籍仅作为可迁移手法，不混淆时代语言），为炼丹/阵法/交易等采用多个 scene facets。未匹配就 NONE，质量权重必须有证据，不能让越长或越多越靠前。
- 无关、污染、版权未授权、超限、重复、同源过多或结果比无学海更差时先**停用该卡**，不自动训练或生成 v3；保留失败原始 SHA 和旧版卡。

## 五、阶段目标、成本上限和验收方式

| 阶段 | 交付物 | 量化目标（计划值，非既成结果） | 停止条件 |
|---|---|---|---|
| 0.BL-0：真实调用链与首批种子 | 代码审计、古籍书目来源、原创玄幻微场景、引用/权利审查 | 原写作入口能证明哪条资料真正入 prompt，先有离线 SOURCE→QUERY→WRITER 回执 | 仅生成索引无真实方法使用，停止灌库 |
| 0.BL-1：来源与场景细化 | 6 部古籍各 8—12 个**核实原件**的场景片段方法，16 类玄幻每类 4—6 个原创情境 | 首批 120—160 个候选方法（全为目标，待审不自动宣称掌握） | 文本只有标签、无动作/限制/后果；版权无法核实 |
| 0.BL-2：真实检索与受控注入 | 与旧 SQLite 共存的方法卡、最相关 1—2 条入写作 prompt、来源证明 | 预登记 32 个多题材查询；抽查相关率目标≥80%，错体裁/泄漏为 0 | 在安静场景乱塞炼丹技法或发送原著段落 |
| 0.BL-3：同模型、同预算三臂实测 | 裸模型 vs 实际 WF G 核心 vs WF G+学海方法；保留全文、实际 provider wire、调用次数和成本 | 先 1 场景来源/长度可用性试跑，再 6 个差异题材；每臂总调用/token 封顶且按真实消耗报告 | 三臂任一无法实际写正文/不断复制上文/成本无上限，立即停止不给人评 |
| 0.BL-4：独立阅读、权利与发布 | 真正盲评与失败修复；版本化回滚、申诉/版权下架机制 | 逐题同时核验文学质量、人物选择、细节自然性与新增成本；有收益才考虑发布 | 质量无改进或误命中/复制风险，不上线此 Skill |

**核心验收**是“学海卡在指定场景确实帮助了同一作者模型产生非模板化的可读正文”，不是拥有多少万字、多少条审稿器或多少个 GREEN 单元测试。三臂预算不同就展示质量-成本曲线，不以仅相同每请求 max_tokens 冒充等预算。原 0.BJ 无效文本、0.AY 缺失模型正文和所有失败记录保留。

## 六、第一批书目矩阵（只登记待验证方向，不假冒读过原件）

仓库已存在七部现代作品历史归档配置（见 tests/test_v33_learn_archived_modern_r2.py），可作为**待授权的比较阅读清单**：

- fanrenxiuxian：资源与风险管理、弱者取舍；
- doupo：身份羞辱与目标反转、训练代价；
- wudongqiankun：宗族关系、胜负后的社会反馈；
- wanmeishijie：少年成长、异域神话细节；
- zhetian：古史遗址、尺度与未知；
- manghuangji：修炼体系、物理与技法层次；

上面的分类仅是**编辑候选标签**，不代表 WF 读过或验证了某部作品中的某段文字。真实片段入库需来源许可、原文物理 SHA、段落定位及复核后另行批准。现代版权作品不得从网页批量爬取到开源 GitHub；任何 R2 中受保护原文未经另行明确同意一律不访问。

## 七、特别保留的 WriterForge 初衷

WF 不是一个复制素材的检索助手。知识库教 AI 什么细节可能有用、细节如何影响人物判断和叙事因果，**不能替 AI 选哪一个情节、强迫文风、写正文、强制删除不满意段落**。保留 V26 选择、V98 滚动构思、V119 精确修订与唯一 NarrativeCore，不增加第二记忆服务。过去无价值尝试要能主动停止。

本轮可以公开宣称的是“具备执行计划与明示来源的首批候选”，**不能宣称积累了几百部名著经验、学习提高或完成真实模型文学胜利**。
