# WF 时间 Skill — 直接从原著正文读取事件候选（2026-11-13）

**状态：原著正文到可定位事件证据的通道已运行；原著因果训练尚未完成。原始书籍与带原文的事件账保留私有，不提交 GitHub。**

## 本轮到底改了什么

上一轮失败是先由助手把连续原著压缩成11条“匿名观察”，再让小模型提出参数。这一步已经丢失原著大量人物行动、说话者、事件发生条件和否定描述，导致输出 `time=time+time` 等空洞公式。改变提问顺序解决不了“输入被提前压缩”的问题。

本次在 **同一个 xianxia-time-rule Skill** 增加 `scripts/raw_episode_reader.py`：直接读取经过严格编码核验的完整原著文件，在指定连续章节内按真实文件顺序建立可逐字节定位的**整行证据账**；然后才按原文句段生成候选事件，分别保留时间短语、活动/约束/资源变化线索、否定词、人物想法/传闻/对白的可疑认识状态。每一条都有真实 byte span、内容 SHA、章节及叙述出现位置。

**绝不把此处的关键词触发直接认定为语义事实、故事时间、正确人物身份或因果关系**。目录标题也是原始文件的一部分，但不能作为“人物修炼了”的事件依据。发现不确定说话者时，明确置为 UNKNOWN，不把“急忙说/沉声问”当人名。读者知道一个信息的章次，不等于故事中这个信息那时才存在。

## 先 RED 后 GREEN 的实际错误

1. **章节标题误识别成事件**：标题中有“修炼”就错误产生练功事件候选。新增失败用例，修正为：保留标题字节凭证，但不将它当人物行动。
2. **使用额度与单次时长漏掉**：在一句话中同时出现“每天几次”和“每次二十多个时辰”时，旧程序没有完整识别两个独立条件。修正后的两个候选标记分别为 `daily_access_quota` 和 `per_visit_duration`，保留原始数字词、约数状态，**不推导精确时长、不偷换为洞府的物理倍率**。
3. **中文说话者误识别**：旧正则把副词当作人名。因此暂时取消未经复核的说话者自动身份确认。这是必要的保守停用，不是“人物归属已解决”。

本地9个合成用例已通过，包括上述发现的失败测试；GitHub [定向 Actions #43421389220](https://github.com/66tyu55/WriterForge/actions/runs/43421389220) 当前通过8个本轮源文无关测试，并保留其他之前时间参数回归。**两份原著输出的每个候选字节锚点和完整章节逐行凭证均可重校验。**

## 本轮仍不能完成的事情

- 事件候选来自通用时间短语和少量活动线索，不是模型理解过的高精度事件。像普通语气中的“死”字、名词“水”可能触发无价值候选，**不能拿候选数当正确率**。
- 人物跨章节身份、别名、代词指向（他/师父/长老/陌生人）、说话者以及各人物只知道的事实，**尚未训练/核验**。
- 叙述顺序不自动等于故事发生的先后；“一夜苦修”不自动等于成功突破；没有原文明示的时间流速不能计算 3×。
- 候选仍不能安全直接喂入 `temporal_delta.py` 作已确认事实。必须先对事件主体、是否真的发生、事件先后、条件生效范围和证据进行语义审核；否则是把错误因果转成持久规则。
- 没有独立第二读者金标准、端到端真实模型直接阅读原著并输出可靠规则的通过记录，更没有对13本书全章节的完整时间模型与后续作品盲测。

## 下一条明确的修复链（不是继续增大参数表）

`完整连续原著 → 来源逐字可追溯的事件候选 → 人物/说话者与视角认知核对 → 真正发生的状态变化 / 信息后来才揭示的区分 → 局部动态时间规则 → 后续未见章节反推测试`。
