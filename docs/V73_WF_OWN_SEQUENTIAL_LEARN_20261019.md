# WriterForge V73｜把“分类、编号、拆章、逐章学习”交回 WF 自己（2026-10-19）

## 用户纠正（本轮唯一核心）

用户说：「这些不是属于WF--如果你替他分类编号章节--直接一本一本的让WF自己训练不就可以吗？」

**确认**：此前 V68—V72 里，助手为 WF 实现了基础“R2 发现→SQLite索引→R2永久持久”通道，但它最多是文档索引基础设施，**不是 WF 自己获得文学经验**。不能由助手在外部先决定每本书的正式文学类别、补齐章节号、挑出“名句”、生成读者评论，再让 WF 把这些当成学习结果；也不能把全文建库的成功当成已训练。

## 修正后的实际执行归属

| 任务 | 责任者 | 证据门槛 |
|---|---|---|
| R2认证、只读分块、临时磁盘、SQLite可查询 | WF I/O 基础代码 | SHA、Range、预算、读写授权 |
| 选择下一本书（不可由GPT点名） | WF LEARN调度器 | 按R2工作队列/冻结进度与预算确定，不重复从头 |
| 给作品分配不随书名变化的内部ID | WF 文档入口 | 完整原文SHA；类别数字不作为作品身份 |
| 初步判定古典/玄幻/仙侠/科幻/历史等 | WF 文学分类技能 | 文件夹名仅是来源提示，模型需要原文证据；无法判定则UNDECIDED |
| 发现章节、编号、原文位置 | WF 文档入口 + 学习流程 | 物理行边界/章次对照；序号缺失、乱码不擅自修补 |
| 每次学习一章 | WF LEARN，且必须独立模型和真实记忆 | 严格先读者PASS A锁定，再分析PASS B；不可偷看未来正文 |
| 八线、人物感知/恐惧、因果、伏笔、读者疑问、经验 | WF文学技能 | 原文可追溯、错判可反证、章节间记忆真实影响后续行为 |
| 复盘、记录失败、学习卡、断点 | WF自己的R2私有学习账本 | 每章独立不可变checkpoint，成功后才继续下一章 |
| 统一文学毕业/等级晋升 | 预注册独立考官 | 原V49失败记录不得覆盖，考生不能自己给自己晋级 |

## 已实现 V73

分支 `v73-wf-owned-sequential-learning` 从已真实通过 R2跨进程持久索引的 V72 单独分出；不改 `main`、不改Cloudflare现有Worker、R2小说和永久索引，也不触发GitHub Actions。

新增 `writerforge/wf_self_learning_admission.py`，**由 WF Python 进程自己处理**一部来源的“入学检查”：核验原文完整 SHA 和原Key，严格UTF-8/GB18030等解码，物理行上识别章头，对候选章次做连续性校验，记录每章原文字节对应的解码文本哈希及行位置。预留第一章的局部区域（学习模型不得看到后文）；不保存或回显私有书名、原文、关键词；不得把目录分类提示升级成自己的文学结论；没有模型/私有学习账本就报告 `WF_DOCUMENT_ADMITTED_LEARN_ENGINE_PENDING`，已学习章数0。

新增 `wf_railway_v73_self_admit.py`，WF自行从四目录元数据中选择预算内的1个 TXT，在 Railway 临时目录进行只读下载与第一轮文档结构检查，结束自动销毁。生产Writer Token在该进程内移除，0远端写、0模型调用、无GPT接触正文。**如果章节边界不匹配或源编码不可靠，保留明确失败/阻塞回执，不编造分类或训练成绩。**

新增 `tests/test_v73_wf_self_learning_admission.py`；Railway新旧55项合成测试。第一次部署 `d50e24c7-ed62-40d5-9dc0-23a956a0f726` 出现1项测试夹具红色：V72旧Mock会读取Railway后来新增的Writer环境Token，使假定“没有写密钥”的测试不再成立。**这不是小说内容或训练算法失败，但确实是测试隔离错误，原红色留档。** 修正V73测试runner在导入任何WF模块前剥离真实Writer Token后，Railway部署 `bb272ee5-a1ef-45d0-8432-9e0f3cad7507` 真正Python跑**55/55通过**，零R2读取与写入、零模型调用、不声称文学学习。

## 接下来不能跳过的两个硬关

**模型/独立决策关**：目前 Railway `wf-python-r2` 只有 `WF_API_TOKEN`（R2读）和 `WF_INDEX_UPLOAD_TOKEN`（R2索引写），没有独立的 `DISCOVERY_API_KEY` 或其他已经验证可用于WF文学分析的模型接入。原 `reverse_real_training.py`、`v31_autonomous_core.py` 等属于旧实验且实际模型有外部接口；它们不能在没连接模型时伪装运转。接入WF自己的规划/阅读/分析模型后，必须全程保持模型的权限、费用预算、先读后析的顺序与第一轮快照签收，且不允许ChatGPT给书的分类/答案。

**WF学习记录的R2持久化关**：现有V72 R2 Worker仅允许 `writerforge/v1/indexes/v1/` 特定格式的SQLite索引对象上传；**还没有为WF文学LEARN的章节自评、错误和经验提供独立的不可变R2日志与签收协议**。不得为省事把学过的章节伪装成V72索引manifest的“literary_verified=false”对象，更不得把临时进程口头输出当成持久学习。需要后续独立扩展受限R2 LEARN日志/快照，保证第一读反应锁定在分析之前、先有R2 checkpoint才解锁下一章。

原V49终审 `THIRD_STRIKE_FAILED` 与第二文学窗口 `LOCKED` 完全保留。**下一阶段属于结构预演/新的隔离学习实验，不能绕过正式锁定直接晋级。**

**真正目标**：WF从R2按自己状态选一本→读第一章→自己解释分类/人物/环境→即时保存真实错误与经验→完成一章才推进下一章或下一本；全程绝不通过助手手工分配编号、文学标签或“标准答案”。
