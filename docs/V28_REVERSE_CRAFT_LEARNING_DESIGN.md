# WriterForge V28 设计评审：临摹倒推、遗忘、双段合并与 90% 晋级

> **设计状态：SPEC ONLY / NOT TRAINED / NOT IMPLEMENTED。** 只规定下一版 WriterForge Skill 的行为，**不执行本轮《武动乾坤》训练**。旧版文学阶梯不能直接替代本规范。当前 R2 《武动乾坤》原文已归档，SHA256 `86a2fd859b424efe0500b4b36713ea8b05d551140650904ffc2ae02eb244ed28`，但有章节编号异常，**全书严格结构核验尚未通过**。试点仅能选通过局部原文定位与顺序核验的片段。

## 0. 核心目标 / 边界

核心不是复刻小说原词句，而是从“我先写、再看原文”的失误里反推：人物在此刻为什么这样注意世界、当时知道/不知道什么、怎样决定；叙述者为什么挑这个细节、使用这种视角/信息顺序/留白；读者因此可以形成什么预期。

- **训练主体是持久运行的 WriterForge 程序 + 私有数据库 + 可替换本地生成模型 + 独立审评器**。ChatGPT 仅做设计、代码审查与运行日志问题定位，不负责在对话里把每段原著人工分析完。“99% Skill + 1% 助手”是**控制权/流程分工原则，不是模型算力占比**；真实生成与语义评价仍然离不开实际模型和审评。
- 不进行模型权重微调；这是**技能的程序化练习、记忆和检索规则更新**。不自动冒充获得大师文笔。
- 不追求 `90% 原著原词句相似` 或同场景重述。90% 是有定义、有独立评审和盲测校准的**叙事能力门槛**，不允许靠 BLEU/词向量相似度、字数、语气模仿或自评凑数。
- LEARN/WRITE 路由依然隔离；“学海原文”不受训练草稿污染。生成器与审评器使用隔离上下文，同一次尝试不能共享对方的隐藏原著或评分。角色、桥段、句式的长片段不得照搬《武动乾坤》。
- 每次只跑**一本、一个窗口、一个写作候选**；下一书与下一窗口必须明确经过门槛，不自动遍历全书。

## 1. 一次训练的流程（两次局部 + 一次合并）

```
校验 R2 edition / 章节局部审计（SOURCE_LOCKED）
        |
短时快读：只提取当前一段的因果/人物认知/转折提纲（PREVIEWED）
        |
隔离写作者：仅接收抽象任务，不见原文措辞和后续剧情（WRITING）
        |
原创练习稿写入短期私有 scratch，hash 封存（DRAFT_SEALED）
        |
原著对照评审：人物感知/因果/叙述选择/读者期待 + 反事实（COMPARED）
        |
分别记录失误、遗忘、机制假说、对照、候选核心（CORE_PREPARED）
        |
写入 SQLite 有界事件证据，提交并确认 R2 轻量核心快照（CORE_DURABLE）
        |
清理 scratch 练习稿；校验清理完成（DRAFT_PURGED）
        |
全新原创、未见过的条件中“闭卷重测”，独立盲评（RETESTED）
        | 若质量达标且核心没有未处理冲突
局部晋级 PASS（否则有限重试 -> BLOCKED）
        |
相邻第二段独立完成上述流程（B PASS）
        |
只拿 A/B 的抽象因果核心，不拿草稿正文，产生一个更长的全新剧情（AB_MERGE_TEST）
        |
新的盲评 >=90 且人物连续性/信息释放均达标 -> MERGED_PASS
        |
节制地推进下一段；达到 max_chapters 则 STOPPED_MAX
```

解释：**第一次快读是获得局部“可写任务”，不是把原作者所有细节剧透给生成器**。对照发生在作者练习稿的内容哈希锁定之后；否则很容易从对照变成照抄。原著后文可由审评器在 COMPARED 阶段读取，但不能回灌给先前的写作上下文和首次读者预测。

对照必须有明确的因果结果：`当前世界事实 -> 人物已有知识 -> 注意筛选 -> 误判/判断 -> 动机和行动 -> 后果`，以及 `叙事焦点 -> 信息排序 -> 读者的推断 -> 反事实改变`。作者“真实心理意图”不可由文本确定，只可产生带支持/反证的写法假说。

### 局部窗口怎样划分

- 先完成本窗口原文/分卷/章节局部序号核验。已知《武动乾坤》存在编号异常，所以不能拿标题正则数量当作全本完整证明。
- 在局部章节里优先按**感知事件 + 决策 + 信息揭示**找到场景边界；避免每固定 N 字截断。每段建议 600–2200 汉字上下文，不包含剧情后文；实际阈值可按模型能力调小。
- A/B 必须相邻且有**可证明的认知、冲突或信息承接**。不相关的两段不能机械合并；若场景过渡不完整，先扩展合适边界，受 max_chapters 硬上限约束。
- 快读提纲最多 12 个抽象事件节拍；保留 source SHA / span ID、谁能知道什么、要解决的矛盾、揭示时点。不得把原文台词或大段原著嵌入生成提示词。

## 2. 必须独立保存的核心训练文件（由 SQLite 投影生成）

SQLite 为**唯一事实源**；下列 5 份 JSONL/JSON 是可重建的有界文件视图，支持独立审阅和未来 R2 归档，而不是五个彼此写入、互相矛盾的“真数据库”：

| 文件 | 内容 | 禁止保存 |
| --- | --- | --- |
| `faults.jsonl` | 漏掉的因果关系、人物动机误判、视角越界、节奏失衡、修正状态、引用证据 ID | 完整练习正文 |
| `forgetting.jsonl` | 闭卷遗漏的认知事实/转折、上次成功后何时又犯、复测安排、稳定性评分 | 练习段落与原文长段 |
| `master_hypotheses.jsonl` | 原著可观察技法、为何可能如此呈现的竞争假说、原文锚点、反事实、支持/反证、置信等级 | 断言作者内心动机 |
| `comparisons.jsonl` | 参考锚点、练习稿 hash、逐维评审分数、评审器版本、结论、是否存在抄袭风险 | 草稿全文、整篇原著 |
| `cores.jsonl` | 可迁移的机制规则（触发条件→作用机制→期待读者效果→失效范围）、支持场景数、反例、版本与合并谱系 | 大段仿写成品 |
| `progress.json` | 单本 max、已通过段数、相邻合并关卡、最近有效事务、下一行动、被阻塞原因 | 任何正文 |

建议本地逻辑结构：
`writerforge/v1/reverse-lab/wudongqiankun/<edition_sha>/`；
真实 R2 结构采用**独立私有命名空间和内容哈希 manifest**，不要修改已有单书原文 blob 和 `libraries/` 成果。默认只有结构核心和哈希进入永久快照。

`CORE_PREPARED` 时只能进入“待审核/未证实”区；不可直接加入写作 Skill 的高信任核心，更不可回流为原文事实。核心批准与失败记录必须在同一事务中落盘。

## 3. “+3 对比”怎样做到真的去重和进步

把用户提出的 `>3 次的核心，按照 +3 对比` 解释成**3→6→9 独立证据升级**（可配置，但不能由反复重跑同一场景作弊）：

- 首次出现：建立 `candidate` 核心，记录适用场景、失败及来源。
- 在**至少 3 个不同叙事上下文**观察到相同因果机制，且经过独立审核：`recurrent_3`，仍是暂定规律，不提升为全局万能写法。
- 达到**6 个不同上下文**（+3），且经反例检查/闭卷写作迁移：`retested_6`。符合门槛才可进入技能候选库。
- 达到 **9 个不同上下文**（再 +3），且不同人物/冲突中仍有效：`generalized_9`，进行作用域聚合与压缩。每升一级保留证据、反例和旧版本链接。

去重不能仅靠语义向量相似：建立 `(problem_type, trigger, causal_mechanism, intended_effect, scope, counterexample)` 的规范化指纹；完全重复可自动折叠为一条，近似重复仅提出合并建议，必须复核是否目标不同或出现反例。旧核心标记 `superseded_by`，不删除来源证据；**不新增一个与旧核心争夺写作入口的第二套 Skill**。

后续核心不是不停 +3 创建新文件，而是更新同一核心的版本与证据关联，并做周期性的闭卷复测。如果无法重新通过，`demoted`，禁止生产写作选用，保留失败事件。

## 4. 90% 晋级门槛：三个不同意义，不能混同

**(A) 局部机制覆盖分（机器可核）**：选定的来源锚点、人物知识界限、因果链、节拍覆盖与反事实证据的**可核部分**，例如应追问的重点是否都被提及。它是证据完备度，不是文学水准。

**(B) 盲评文学效果分（依赖实际独立评审）**：候选稿和独立参考标准在不暴露作者/模型来源的条件下，按同一任务说明评价人物可感知性、决策可信度、情节因果、视角一致性、信息释放、节奏、语言清晰度与原创性。给出逐维证据和评审分歧，才允许称“文学效果分”。**与《武动乾坤》原文字面相似不计入成绩。**

**(C) 迁移留存分（闭卷）**：删除练习稿后，必须在新人物、新情境下独立生成，检验核心是否能调取且正确使用；两段合并和延迟重测同样要达到标准。

建议试运行门槛：
- `quality_score>=90/100`、`transfer_score>=90/100`、`evidence_complete=true`；人物认知/行为因果/信息策略等关键维度各 `>=85/100`。
- 抄袭/近似重述硬闸门、角色信息越界硬闸门、无真实外部评审硬闸门，任意失败即 **BLOCKED**；不同评审分歧过大，则 `needs_review`，不能自动通过。
- 首两段、合并大段、后续跨章测试 **分别设门槛**。不得只把两段 95、95 的分数取平均，就自动判大段合格。
- `90` 是**经校准的内部质量目标值**，不能数学地宣称已达到“大师写作能力的 90%”。要有真正独立读者/作者专家与同模型无 Skill 的 A/B 盲评、多样样本、可信区间后才可报告对外能力提升。未接评审器则停在 `REVIEW_BLOCKED`，不可用模型自评补齐。

## 5. 遗忘要故意测，不是简单再读原文

第一次 PASS 后，立即清除生成器上下文中的原文对照、练习稿和揭示。下一次隔一段新剧情，抽取一个不泄露原著的同机制原创任务：

- 如果能写出来、结构正确、能解释为什么该角色会感知和行动，则 `retained`。
- 如果只会背核心术语但不能用，则 `forgotten_or_not_transferred`，退回候选。保留失败类别、原因、重测间隔及版本。
- 若相同误区在 3 个**独立**上下文发生，可建议升权为“需特别警惕”规则；不能用原任务的反复失败增加 +3 计数。

## 6. 与既有代码的实际兼容风险

检查当前仓库发现：
1. `writerforge/literary_ladder.py` 将每次 `body` 写入 `literary_training_attempts.body`，并在 `writing_runs/literary_ladder/<run_id>/draft.md` 保存完整稿。现有最大 400 次限制仅限制**次数**，不支持“提炼后无正文持久化”。
2. `writerforge/r2_storage.py` 的 `_logical_study_digest` 还包含 `literary_training_attempts.body`。如果沿用旧流程，完整草稿可能进入**不可变的 R2 快照**。后续“删除本地文件”无法追溯清除此前快照。
3. 原始 `scene_learning.py` 已有先读锁定、后文验证和短假说，但**没有**局部原创稿自动销毁、盲评双关、2 段合并、+3 频次证据的状态机。
4. `verified_flow.local_chat_completion` 只允许本地 loopback 模型服务；**GitHub Actions 本身并没有现成可直接调用的真实文学模型与独立审稿器**。因此本阶段不能因为新增 workflow 就宣布 90% 文学训练完成。

兼容方案：新建 `ReverseCraftCoordinator` 接现有运行时状态路由；`PREVIEW/CRITIQUE/CORE` 属 LEARN 任务，`DRAFT` 是一个隔离 WRITE 子调用，子调用只返回短期草稿供评审，不污染 Canon、Reader、作者写作 companion 或现有 `literary_training_attempts` 表。建议新建独立命名空间的核心证据表，与正文临时区严格隔离；首版不能修改旧表来冒险迁移。

## 7. 内存、循环、持久化与隐私安全不变量

| 风险 | 不变量 / 处理 |
| --- | --- |
| 无限循环补写直到 >=90 | 每单元最多 3 个独立候选；同一候选最多 1 次针对性修订，达到上限后 `BLOCKED_QUALITY`，由用户决定更换内容或放宽目标 |
| 审评始终要求重测 | 最多 2 次单元复测、最多 2 次双段合并候选；每级上限后阻塞，不自动跳过 |
| 单书永不结束 | 用户可设 `max_chapters`（试点默认 3）、`max_units_per_chapter`（默认 6）、`max_model_calls`（每单元 <=12）、`max_wall_seconds`、`max_total_tokens`；任一预算耗尽 STOP |
| 反复同一核心 +3 | `UNIQUE(core_id,source_work_id,scene_id,context_hash,assessment_version)` 及按独立上下文去重；同次重跑不得增加频次 |
| 内存泄漏 | 同时一个 scene window、一个草稿、一个审评结果；有界输入/输出、批次 cursor 读取；无全书数组/全局闭包/无上限队列；每步断开模型会话引用 |
| 临摹文本永久占盘 | 草稿仅在临时隔离工作区；禁写主 SQLite `body`、R2、GitHub、CI Artifact、日志。所有异常路径 `finally` 清理，重启时隔离清扫器按 TTL 找遗留。删除不是对 SSD/备份的可验证安全擦除，故**原则上不让正文进入持久备份** |
| 比较完成但未备份就删稿 | 先写入受控摘要与审核记录并 SQLite COMMIT，再上传**轻量**核心快照并全新回读校验；成功后清理草稿。R2 中只允许结构证据和小型哈希 manifest；失败则 `PERSISTENCE_BLOCKED`，不晋级，scratch 在 TTL 内隔离等待重试 |
| 崩溃重复执行、重复备份 | 状态迁移 CAS / compare-and-swap、幂等键 `edition_sha:chapter:unit:stage:attempt:config_rev`；最多一个执行租约，超时接管核对 SQLite checkpoint；不得重评当作新证据 |
| R2 快照无限增长 | 轻量核心独立快照按工作单元 checkpoint；每个阶段合并、内容寻址去重；对非保留快照按明确 R2 生命周期策略做可验证的安全清理，保持少量钉住版本与必要审计。先核实引用再垃圾回收，不删最后可恢复版本 |
| 因训练触发写作架构无限增长 | WriterForge 的 LEARN/WRITE 路由保持单一协调器；最多同时激活 1–2 个现有 Craft 子功能；禁止在每次失败时注册新 Skill/新全局监听器 |
| 断线、模型失联、异步超时 | 单个模型请求 <=120s（可配置至工具上限）、取消令牌、失败步阶段代码、任务幂等恢复；GitHub logs 仅输出 run_id/hash/阶段/错误类，不能泄密 |
| 来源不同版污染 | 原文 `SHA256`、段落锚点、章节范围、分析器版本是所有核心的复合键；编辑错误/不完整章节阻止前进。试点可在已核过的局部段落做实验，不能声称整本全局覆盖 |
| 长期只学原著风格 | 写作者不见原著完整措辞、人物与剧情强制重构；近似文本检测失败不得晋级。全新创作外部盲测才是可迁移能力证据 |

**R2 细节**：现有 `R2StudyVault.backup` 会快照整座 SQLite，原文作为 `source.txt` 可附带上传；其 `edition` 重用依据未包含未来新训练表就可能错误复用旧快照。V28 要么单独实现轻量 `ReverseCoreVault` 并覆盖 manifest /恢复完整性验证，要么新增表后同步更新 `_logical_study_digest`；**不准**把未审查的新核心塞进旧 R2 学习库后继续声称 `verified`。

## 8. 单本《武动乾坤》试点验收方案

试点不直接启动。实施前需要：
- 固定原文 SHA，验证准备试验的 **章节局部** 连续、来源确实没有缺失；不复用“完整原文入库”虚假成功标签。
- 先设计 2 个有因果承接的 **小场景** A/B，每个各自快读/原创练笔/评审/删稿/闭卷复测，目标两者达到 `90` 的分项门槛；未通过停在当前段，不自动放宽。
- A+B 再写**全新**多节拍原创剧情，不复述《武动乾坤》的原情节；同样 90 分闸门通过后才能进入第二对段落。
- 首次试点 `max_chapters=3`、`max_units_per_chapter=6`、`max_candidate_drafts_per_unit=3`、`max_merge_attempts=2`；全部是可调的**硬限额**，不是系统必须写满的目标。
- 当没有真实模型/独立审评服务接入时，仅运行**纯合成回归与技能状态机测试**，写明 `MODEL_UNAVAILABLE` / `REVIEW_BLOCKED`，不伪造 90 分。

## 9. 在真实训练前必须通过的工程测试

1. **有限状态**：所有迁移是单向 DAG，只有 `new_attempt` 显式增加预算并创建新 attempt_id；禁止状态自身递归重试。3 次失败能正确停。
2. **重启幂等**：在每个状态 COMMIT 前后模拟 kill/restart，不能越过审核关或产生重复 core +3。
3. **内存峰值**：用合成 10,000 次小窗口循环验证内存随次数不单调上升（容忍 GC 波动），活跃模型会话、打开文件句柄和数据库 cursor 不随次数累积。
4. **持久化失败注入**：R2 超时、指针竞争、部分上传、SQLite locked、磁盘满、恶意异常，不允许晋级；旧 latest 必须保留。
5. **零原文草稿泄露**：检查仓库、CI Artifact、日志、主 SQLite、R2 对象清单不含测试 draft 特征字符串；崩溃 scratch TTL 清扫成功。
6. **质量假通关测试**：审评未配置、只有模型自评、维度空值、评分不一致、文字近似复制、同一场景重复刷分，全部 FAIL CLOSED。
7. **合并与衰退**：A/B 各自通过但 AB 长剧情失败时保持段落通过状态，不可推进下一个窗口；复测衰退可暂停生产核心。
8. **核心语义去重**：同机制同作用域折叠；同词不同因果不得误合并；多次合并保留反例与审阅谱系。
9. **来源与运行隔离**：错书、错版本、缺章、跨项目读取、同书并发、LEARN/WRITE 状态混用全部拒绝。
10. **R2 干净恢复**：新进程从 checkpoint 和核心快照恢复，不依赖 GPT 本地会话；恢复时的批次和哈希数等于备份前。
