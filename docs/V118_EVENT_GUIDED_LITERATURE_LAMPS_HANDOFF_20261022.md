## 用户思路与决议

用户要求 WF 继续完善底层文本追踪与文学生成的逻辑思考，不满足于大量逐章阅读和机械拆解；希望像道路照明一样“在恰当位置短暂照亮下一步”，在保留原创自由的条件下指引剧情走向。要求不新增模型与付费文学测试，先用 V113 与 V114B 已封存原稿检验。

**严格区分两条路线：** 叙事连续性来自“先前可信状态→动作候选→前提校验→下一段受限状态”；文学经验来自“特定场景问题→阅读定位证据→候选策略→反例→独立迁移核验”，不能从“读取文章”直接宣称变聪明，也不能把软件指令当模型微调训练。

## 下一步实施纪律

1. **不再为“继续训练”随机堆章数。** 优先完成调度器基于真实语义证据的错误分类与选择效果回归；V118 目前只验证了提示在对的条件下被选择，**没证明文本作品改善**。
2. 已有 `VerifiedWritingFlow.prepare` 包含 `ExperienceDecisionBridge` 的正式、审核经验决策路径以及 `SceneCraftTeacher` 的外部教学候选，V118 目前只接了静态 `CraftEngine` 的单技巧路灯。下一阶段可通过既有 V61 审签经验决策接入到“文学路灯”，但要先保留未审情况为 SKIP、避免让 V65 teacher 模拟卡自动冒充自主阅读成果。
3. 从多种文学体裁做 **缺陷驱动的阅读**：只选已证明的缺陷（因果、人物动机、知识视角、资源代价、对白博弈、节奏）。每个经验卡必须含原句定位、适用条件、不适用条件、失败反例、检验方式，经过独立审读与同模型留出新题对照才可能晋级。
4. 不为强化监控强制五步式、八节拍、字数定额或均匀撒提示；文学静默优于无证据的介入。系统要有优先级/冷却/熄灯/预算，不能让控制模块压倒真正的小说。
5. 训练不是修改大模型参数。WF 目前做的是软件侧的结构化来源阅读与条件经验路由；真实权重训练/微调未开展，也无长期文学改进结论。
6. **冻结新的付费文学生成**，直到对新分支完成零模型冒烟、多样场景误报审查、确认恢复/跨章引导后，再独立预注册有限预算的真实文学 A/B。V49 真实历史失败与原前15章记录不改。
