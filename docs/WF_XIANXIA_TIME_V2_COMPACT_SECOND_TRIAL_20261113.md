# 修仙时间规则 V2 — 两次真实写作测试与停止条件

## 第一轮：真实三组原始回复（已经执行，保留）

[GitHub Actions #43389602974](https://github.com/66tyu55/WriterForge/actions/runs/43389602974) 真实运行了本地固定 SHA 的 Qwen2.5-3B，零付费 API，零重试。无参数、洞府流速 1:1、洞府流速 3:1 三组各一条回复，JSON 全部有效。

**写作实效失败**：三组时间事件表都只有“入洞修炼 6 世界小时”一条预置行动；没有实际尝试突破、修堤、救人或洪水后果。普通组和 ×1 组累计 12 实修小时，×3 组累计 24 实修小时，机械时间重放正确；但正文只是宣称“决定做出选择”或“必须尽快突破”，没有执行行为，篇幅也明显低于事先要求。**程序判断的 PASS 不是作者规则的 PASS。**

另有实测问题：模型直接把职业重复当名字，文字出现“灵田佃户灵田佃户”，提示词要求没有进入自然叙事。原始模型回复和计费量记录在该 Actions 的 artifact 内，不能修复后覆盖它。

## 发现的接口根因

本轮并不是时间单位推算失败，而是把 1,700 多字的底层参数 JSON 连同逻辑要求直接交给小规模作者模型；模型简单复述字段，没有把规则变成自主行动。这不能单凭一个 3B 模型认定所有大模型必败，但足以说明**原先的写作接入方式没有验证成功**。

## 第二轮：只改变参数进入写作的方法

保留同一个随机人物、洪水时间、突破门槛、洞府倍率差异、模型、种子。使用 `.agents/skills/xianxia-time-rule/scripts/time_bridge.py` 从已重放的 6 世界小时自动生成**当前实际可行条件**，而不把参数表、代码或固定剧情模板交给作者：

- 当前世界时刻 1006，洪水在 1008，外界剩 2 小时
- ×1 组累计实修 12 小时，仍差 8 小时，不可能在当前时刻成功突破
- ×3 组累计实修 24 小时，具备尝试条件，但成功绝不保证
- 守夜人独立推进 6 小时的时间，不能因为主角闭关而停止行动

重新用相同本地模型生成两个**纯小说正文**，不强迫它同时写 JSON 事件账本。要求一次具体行动及后果，可救人、误判、继续修炼、放弃或者失误，禁止仅以“他决定行动”结尾。仍然是一次探索性实验，**不是独立盲测或小说文学质量训练**。

### 预注册停止标准

1. 模型正文必须呈现实际行动及一个后果，不能只复述设定或宣布将要做决定。
2. 不得让 ×1 组在 1006 时刻未经实修便突破或施展二境术；×3 组可不尝试突破，也可失败。
3. 必须尊重外界仅剩两小时、守夜人自主活动、以及人物认知限制。
4. 要求 400–700 个汉字作可供读者阅读的完整短场景；未达且缺行动，视为失败。
5. **任何上述失败都保留**，不对同一任务继续刷模型或靠加检查模块掩盖。没有独立人工盲评，不宣称文学能力提高。

第二轮属于在看到第一轮结果后作出的**透明方法修正**；即使成功，也只能说明短上下文约束方式适用于一个冻结的原创故事，不证明从完整小说中学会世界运行。
