# WriterForge 0.X — 先用失败测试击穿 WF，再修 WF：错误码碰撞、修订后状态重建、重复原句漏检（2026-10-25）

## 原则纠偏

用户明确指出：**测试是为暴露 WriterForge 的缺陷，从而修复 WF；不是逼小说 AI 迎合系统，也不是让 WF 迎合模型说 `MOVE_ON`。**

因此本次**没有追加一轮文学模型调用**。真正需要修的是模型再优秀也绕不过的 WF 软件真值边界：检测遗漏、伪安全、误拦、旧证据无法结案、下游沿用了旧来源。模型的 KEEP/MOVE_ON 是审美/创作选择，不能替代系统的源一致性验收；WF 更不能替作者生成文字。

**执行环境**：只改 `refactor-unified-scene-delivery-audit` 开发分支。不改 `main`、Railway、R2 原小说、正式 Canon、原有真实 DeepSeek 回包或旧文学样本。不重做已经完成的小说训练，也不加额外文学模型/第二记忆。

## 三项真实 WF 错误（不是 AI 文学失败）

### WF-0X-01：V119 以“风险码”而不是“风险身份”判断修订

- **旧行为**：旧文“铜牌还在木匣/又被取出”，修订后的文本却换成“银牌还在铁箱/又被取出”。两稿都仅有同一个 `NEEDS_SOURCE_RELATION_REVIEW`，旧 `compare_source_repair_impact` 可能误认为没有引入新问题。这会令“改错 → 造出另一个错”难以被检测。
- **修复**：在原 V122 的 `physical_relation_issue_keys` 依据每条具体的物品字面、接触点、关系类别和来源身份构建 SHA 指纹；V119 原 `preview_revision` 返回旧/新**多重集**，`compare_source_repair_impact` 直接比较新增、消失、仍存在的具体风险。相同错误码不再掩盖不同物件冲突。重复出现的同一风险也按次数计，不当成一项。
- **反例**：旧风险替换为另一个、原风险保留又新增另一个、只修无关字句而原风险保持。所有输出仍只是来源结构判断，不是文学好坏。

### WF-0X-02：V114 没有 V119 修订后的旧状态重建入口，旧疑问可能永远堆积

- **旧行为**：0.W 已能签名携带 8 条未证关系跨章，但是合法的 V119 来源修改并不能直接触发原 V114 候选状态**从合法父版本重新归约**，导致纠正了源码后仍被旧版本的候选债务污染，或调用者误用旧下游状态。
- **修复**：原 V114 中增加 `replay_revised_source_checkpoint`，检查原完整 V114 SHA/版本、真实 V119 预览签名、修改范围的原文/补丁/未改前后缀字节 SHA、父快照身份，再用原 MIT Novel Studio reducer 重新执行编辑后的原文，返回**新签名、非 Canon 的候选快照**。旧章节遗留的问题必须保持，只有本次被真实修改而确实消失的来源风险才能退役。新稿新增问题不得凭文字变化被自动清零。
- **反例**：修订真的去掉旧冲突、改无关句子旧问题仍在、伪造候选 SHA、错用旧父版本、重建第二章时旧第一章未证风险必须保持。
- **未完成的工程限制**：此接口给出了新版本快照和“下游必须从新父版本重建”约束，**目前不能宣称所有实际作业/长篇旧章节自动完成了全部派生图的废弃和重生**。G 的原局部 rewind 路径仍须单独进行实际运行与跨章版本链验收。不能拿事务回执当改稿完成。

### WF-0X-03：V122 原句重复时整个物理状态被静默跳过

- **旧行为**：同一段两次写“铜牌还在木匣里”，然后说“已从木匣里取出”。旧审查要求 `prose.count(quote)==1`，把两条重复的真实物件状态完全忽略，从而把有冲突的句子漏检。
- **修复**：V122 原现有来源片段使用 `source_sha256 + source_start/source_end + source_quote_sha256` 定位**每次**重复出现的原句，原 G 的 `_physical_relation_source_hold` 用同样的位置核验，不再以全篇文字唯一作为这些物理事件的必要条件。单纯重复陈述不自动构成矛盾；重复状态碰到相反状态时必须能检出来源疑问。
- **测试**：真正重复同一句 + 后续相反状态，期望保留三条物理主张、两对待审风险及有效 HOLD；只有重复而无相反动作则不标冲突。

1. **错误优先**：优先构造使 WF 错误地显示 SAFE 的具体中文原稿；保持旧真模型失败原文不变，作为持续攻击样本。

3. **通过条件**：同时证明旧误判不再存在、合法留白/顺序/不同对象不被连坐、状态不静默丢失、来源修订不会新造同类错误、没有冒用上一版派生状态。绿色仅为软件工程证据。
4. **文学评价独立**：真实 AI 文学创作和人类审美复评是后续独立验收项，不是本次发现并修复 WF 底层 bug 的必要条件。**AI 的 `MOVE_ON` 既不能洗白 WF 的漏洞，也不能自动证明 AI 的稿子错误。**
